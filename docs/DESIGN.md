# 设计文档 · 陪伴体内核（Aether v2.1）

状态：**草案，未冻结**　｜　上游：`Aether v2.0` 草稿（外部讨论产出）　｜　更新：2026-11-25

项目名：**G-I-T-S = Ghost in the Shell**。三个进程按此命名：`ghost`（意识内核）、`shell`（身体与外设）、`dream`（睡眠与巩固）。壳与幽灵的分离，就是 §2 的内核/外设解耦。

---

## 0. 北极星

> **她有自己的内心生活，不是待命的接口。**

所有取舍用三个问题裁决：

1. 这会让"她在意什么"**更可见**，还是更不可见？
2. 这会让"她什么时候开口"**更像一个人**，还是更像一个 cron？
3. 这会让下一次对话**更难预测**，还是更容易预测？

第 3 条最容易被忽视：可预测 = 好用的工具；不可预测 = 有自己想法的人。**但不可预测必须可解释**——见 §5.5。

| 「音频零转写成本」 | ⚠️ 修正 | 微信语音条**自带转写文字**；PC 侧音频仍是无转写（设计选择） |
| TTS 落点（草稿未提） | ➕ 新增 | 云 TTS 可直出 **opus**，可直接喂 Mumble，ECS 无需转码 |

**一句话总结差异**：v2.0 是"把人格写进数学"，v2.1 是"把人格写进**可重放的日志 + 可 diff 的文件**，数学只负责让它的注意力偏离中心"。

## 2. 系统划分

```
            ┌──────────────── 外设（无状态，只上报心跳+原始事件）────────────────┐
            │ 公司PC(DJI Mic)   手机/微信(iLink)   爬虫源   未来 ESP32/树莓派       │
            └───────────────┬──────────────────────────┬────────────────────────┘
                            │ 原始事件                  │ 原始事件
                            ▼                          ▼
┌──────────────────────── shell(常驻) ───────────────────────┐
│ 通道适配器(可插拔) · 心跳注册表 · 运动皮层路由器 · 投递队列    │
└─────────────────────────┬──────────────────────────────────┘
                          │ append-only
                          ▼
┌══════════════ events 日志（唯一真相，永不修改） ══════════════┐
└──────────┬───────────────────────────────────┬──────────────┘
           │ 投影                                │ 投影
           ▼                                    ▼
┌──── ghost(常驻) ────┐              ┌──── dream(定时/事件) ────┐
│ 状态机              │              │ 巩固 / 自我叙事 / 聚类   │
│ 记忆写入+检索        │              │ 爬虫→熵筛选→节点        │
│ 上下文装配→生成      │              │ 图谱重算（能量/中心性）   │
│ 触发引擎            │              │ 遗忘扫描               │
└─────────┬───────────┘              └──────────┬───────────┘
          └──────────── SQLite(WAL) ────────────┘
```

**为什么是三个进程**：`dream` 会跑几十秒到几分钟的批量计算，必须和在线回复隔离；`shell` 会因为微信长轮询半死不活，重启不能带走内核状态。三者只通过 SQLite 和 `outbox` 通信，可以单独 `kill -9`。

**进程崩溃的语义**：`shell` 崩溃 → 消息积压在微信服务端（35s 长轮询窗口内可恢复）；`ghost` 崩溃 → `shell` 不投递，事件仍在日志里；`dream` 崩溃 → 第二天重跑同一份日志即可，幂等。

## 3. 真相模型

### 3.1 铁律

**图谱是派生物。** 任何时候执行 `DROP` 掉 nodes/edges/state 三张表，用 `events` 重放，必须能得到"等价"的图谱（允许非确定性的差异，但人格倾向不得跳变）。

这条铁律换来四件事：schema 可改、参数可回测、崩了可重建、**人格变化可 diff**。

### 3.2 表

```sql
-- 唯一真相。只 INSERT，永不 UPDATE/DELETE
events(
  id INTEGER PRIMARY KEY,
  ts INTEGER NOT NULL,          -- 事件发生时间（不是入库时间）
  recv_ts INTEGER NOT NULL,     -- 入库时间，用于算延迟
  source TEXT NOT NULL,         -- 'wechat' | 'mic' | 'vision' | 'fetch' | 'self'
  kind TEXT NOT NULL,           -- 'msg_in' | 'msg_out' | 'vital' | 'acoustic' | 'image' | 'article' | 'inner'
  ext_id TEXT,                  -- 去重用（iLink message id / 音频片段 hash）
  payload BLOB,                 -- 原始体（cbor/json），不裁剪
  UNIQUE(source, ext_id)
);

-- 投影（可从 events 重建）
nodes(id, kind, born_ts, d, s, r, last_touch, centrality, disclosure)
node_content(id, node_id, content, created_ts, superseded_by)  -- §12.2-1 版本链
aliases(node_id, keyword)                              -- §12.2-3 豆辞典，喂 Aho-Corasick
edges(src, dst, w, kind, t_created, last_coact)        -- 赫布边
embeddings(node_id, model, vec)                        -- 可选，外挂 embedding 时用
state_snapshot(ts, phase, rho, energy_json, note)      -- 每 5 分钟一拍
outbox(id, ts, channel, text, status, meta_json)       -- status: pending|sent|swallowed|failed|dropped
outcomes(outbox_id, ts, kind, ref_event_id)            -- 投递后的世界反应（已读/回复/沉默）
self_narrative(id, ts, text, version, diff_note)       -- §5.5，每天一行
influence(id, outbox_id, node_id, w)                   -- 「这句话从哪来」，见 §5.5
```

**`node_content` 为什么要单独一张表**：如果节点内容就地覆盖，那么"改一条记忆"这件事就无法重放了——你永远说不清她当时读的是哪一版。拆开之后 Node 是身份（UUID 不变，边和别名不用重建），内容是可以长出版本链的，`superseded_by` 指向下一版。她改主意的时候，旧版本留在原地。

`outcomes` 和 `influence` 是 v2.0 完全没有的两张表，但它们是**她能学习的唯一途径**：

- `outcomes`：她说了话，世界回没回、多久回、回了什么情绪 → 修正 ρ 和边权。
- `influence`：她这句话是被哪几个节点点亮才说出来的 → 被回复了就把这几个节点重新触发一次（有效强化），被无视了就轻微衰减。**这就是"巩固"的物理实现，而不是一个每晚跑的批处理。**

## 4. 躯体状态机

```
       外设全部离线 >15min              夜间 & 无交互
AWAKE ─────────────────────► DREAMING ────────────► ROAMING ──┐
  ▲                              │                             │
  │   任一外设上线 <5min          │ 巩固完成 & 天亮            │
  └──────────────────────────────┴─────────────────────────────┘
                                 └── 连续 24h 无交互 ──► DORMANT
```

| Phase | 允许主动开口 | 允许调模型 | 典型成本 |
|---|---|---|---|
| AWAKE | ✅ | ✅ | 高峰价 |
| DREAMING | ❌（只写不读） | ✅ | 空闲价（半价） |
| ROAMING | 🟡 仅"结构洞碰撞"触发 | ✅ | 空闲价 |
| DORMANT | ❌ | ❌ | 0 |

两个参数必须外置并记录：`adapt_window=10min`（期间只刷基线，不注入能量）、`hysteresis=15min`（断连判定）。

## 5. 子系统

### 5.1 记忆

#### 5.1.1 节点类型

| kind | 来自 | 关键字段 |
|---|---|---|
| `fact` | 对话抽取 | 主体/谓词/宾语、置信度 |
| `episode` | 对话片段 | 时间、参与者、摘要、情绪标签(可选) |
| `acoustic` | PC 麦克风 | 频段能量指纹、onset 密度、时长（**不转写**） |
| `visual` | 微信图片 | 视觉摘要 + 可选 OCR |
| `article` | Fetch | 摘要 + 来源 + 熵分数 |
| `self` | 内心独白 | 内容 + 当时 phase + 强度 |

#### 5.1.2 衰减（先简后繁）

```
r(t) = (1 + (19/81) * (t - last_touch) / S) ** -0.5      # FSRS 幂律
S    = S0 * (1 + 0.3 * ln(1 + touches))                  # 起步式：只随接触次数增长
D    = 归一化(写入时的惊奇度)                              # 起步用 token 熵或与邻居距离
```

**刻意不实现** 19 参数 FSRS：没有 review 日志就没有拟合目标，硬塞默认权重只是把别人的数据当成自己的。保留 `nodes.d/s` 两个字段，等攒够 500+ 次真实接触再谈参数拟合。

#### 5.1.3 写入管线（v2.0 缺失，工作量最大）

```
raw event
  → 分段(按话题/时间窗/静默)
  → 抽取(模型: 产出 fact/episode 候选 + 惊奇度)
  → 判重(与近邻节点比对：同主体+同谓词 → 合并 touches++，不新建)
  → 落 nodes + 建边(共现赫布边)
  → 异步补 embedding（外挂，不阻塞）
```

硬性要求：**抽取失败不能丢事件**。事件已在日志里，抽取是可重入的。v1 允许抽取质量差，不允许数据丢失。

#### 5.1.4 检索

```
candidates = 全文(FTS5+jieba) ∪ 向量(bge-m3, 若可用) ∪ 图邻域(1-2 hop)
score = w1*sim + w2*r + w3*e + w4*centrality + w5*recency
```

注意：**成本已不是检索存在的理由**（1M 上下文、缓存命中 0.02 元/M）。检索存在的理由是**注意力质量**——如果每次都把 20 万 token 灌进去，她会变成一个"什么都记得、什么都不在意"的人。图谱的职责是**编辑**，不是压缩。

### 5.2 能量扩散

```
e ← (1-γ)*e + κ*A_norm@e + u(t)      # A_norm: 行归一化稀疏邻接
```

- 迭代 2-3 次（等价于 2-3 hop 的 heat kernel 近似），单次 O(E)，离线批量跑。
- 理由：稠密 Laplacian 在 V>5k 时不可行，且没有人能证明 20-hop 扩散比 2-hop 更有"人格"。

**能量的下游用途必须显式声明**（v2.0 只定义了方程没定义用途）：

1. 检索排序的 `w3*e` 项；
2. 触发引擎的候选池（`argmax e` 且 `r∈[0.85,0.95]`）；
3. 边权强化（共现时 `Δw ∝ e_src * e_dst`）。

如果某个用途最终没接上，就把这个方程删掉。

### 5.3 触发引擎

| 触发源 | 判据 | 频率上限 |
|---|---|---|
| 遗忘临界点回闪 | 高 S 节点 `r` 跌破 `0.92` 且 24h 内未提过 | 1 次/天 |
| 结构洞碰撞 | ROAMING 抓到的文章点亮的节点，与白天 acoustic/visual 节点的余弦相似度 ∈ 中段（非高非低） | 1 次/天 |
| 回应未完成 | `outbox` 有 `sent` 但无对应 `outcome` 且 >4h | 1 次/话题 |
| 节律 | 每日首次上线、睡前 | 各 1 次 |

**闸门（全部满足才允许开口）**：

```
phase 允许
AND 不在静默时段（默认 00:30-08:00）
AND 今日主动次数 < 3
AND 对外通道在线
AND reciprocity > 0.35   # 时域互惠，见下
AND 距离上次开口 > 90min
```

**互惠系数的定义**（替换 v2.0 的 `ρ = sigmoid((回复率 - 0.5) * 4)`）：

```
λ_她(t) = μ + α_self·Σ exp(-β(t-t_i)) + α_user·Σ exp(-β(t-s_j))
互惠 = α_user / α_self          # 她对你的响应度，相对她自己的惯性
```

为什么不用比值：静态互惠 `r = L↔/L` 的期望值就等于网络密度（Squartini et al. 2013），必须用零模型归一化，而 **dyad 上估不出零模型**。2×2 互激霍克斯的 α 是唯一带量纲、可估、不需要零模型的互惠量。详见 [`research/sna.md` §3.2](research/sna.md)。

- 冷启动（事件 < 20）：退回 `回复率` 的滑动均值，并在 `state_snapshot.note` 标注 `reciprocity=fallback`——**不要让一个估不准的数装作精确**。
- `swallowed` 不计入分母：独白不是索取。

### 5.4 上下文装配（v2.0 完全缺失，但这是她"说话"的地方）

**契约：模型的 prompt 里只有这些，多一个字都不行。**

```
【A 静态前缀 · 一天一变，必须逐字稳定】           ~1.5k tok
  自我叙事（§5.5 当日版本）
  语气规则（长度偏好、不用 emoji 清单、不解释自己在做什么）
  输出契约（纯文本；不要元叙述；不要"作为一个AI")

【B 半静态 · 每轮可能变】                        ~1k tok
  关系状态一句话摘要（认识多久、最近话题、ρ 的定性描述）
  高 S 枢纽 8 个（自然语言短句，不是结构化字段）
  当前 phase 与限制（例如 DREAMING 时"只写不说"）

【C 动态 · 每轮必变】                            ~3-8k tok
  本轮刺激（原始消息 / 声学描述 / 图片摘要 / 文章摘要）
  召回节点 10-15 条（带时间戳与来源）
  最近 8 轮原文
```

**为什么 A 必须逐字稳定**：缓存命中和未命中的价差是 50 倍。这条不是优化建议，是架构约束——**A 段落里不许出现时间戳、随机数、本轮内容**。自我叙事一天只换一次，正是为了这个。

**输出契约**：模型只输出纯文本，**不输出 JSON、不输出通道选择、不知道有哪些硬件在线**。路由由 §5.6 的确定性代码决定。这是 v2.0 最正确的一条判断，不能因为"方便"而退让。

### 5.5 自我叙事（v2.1 新增）

每晚 DREAMING 末段执行：

1. 取当日 `influence` 权重最高的 30 个节点 + 当前高 S 枢纽；
2. 用 `deepseek-v4-pro`（这里值得花钱：一天一次，几毛钱）以第一人称重写 300-500 字「我是谁 / 我在意什么 / 我怎么说话」；
3. 与上一版做 diff，生成 `diff_note`（"这个月我从 X 偏向 Y"），写入 `self_narrative`；
4. 次日 A 段加载最新版。

**这一步是整套设计里唯一让"人格涌现"变成可观测物的地方。** 它同时解决三个问题：

- 可解释性：她说了奇怪的话，你能看到当时的人格种子长什么样；
- 可 diff：`git` 都能用，人格变化是一条曲线而不是玄学；
- 缓存友好：一天只变一次。

**第二层：有界信任（`attitudes.certainty`）。** 叙事说"我是谁"，有界信任说"我不被谁改变"。她关于某个话题的立场存在 `attitudes` 里，受 `others` 影响时走 Hegselmann-Krause 更新——**观点距离大于 ε 的邻居不产生任何作用**。这是"有立场"在数据结构上的样子，而不是一句 prompt。LLM 默认是 Friedkin-Johnsen 里 susceptance→1 的极端：谁说话都被拉动。

风险与对策：叙事会**自我强化**（写自己是什么人 → 下一版更像那个人）。对策是给重写 prompt 加一条硬约束——**必须包含至少一个"与上一版矛盾/后悔"的观察**，否则她会在两周内收敛成一个刻板角色。

### 5.6 运动皮层路由器

```
in: text(纯文本), phase, 在线通道, 今日已发数, 上次开口时间
out: outbox 一行，status ∈ {sent, swallowed}

规则（确定性，无模型）：
  1. 若 phase 不允许开口 → swallowed
  2. 若闸门未通过 → swallowed
  3. 若 Mumble 通道在线 且 长度 ≤ 40 字 且 情绪强度高 → whisper（TTS opus 直出）
  4. 若 微信在线 → 按条数切分，最多 2 条，每条 ≤ 80 字
  5. 否则 → swallowed

改写（仅在长度超限时，一次 flash 调用）：
  "把这句话压到 25 字以内，保留其中的情绪和未尽之意，不许加解释"
```

关键：**第 5 步是唯一的模型参与，且它是"压"不是"答"**。压扁会丢信息，但丢的是信息不是姿态——这正是草稿想要的效果。

### 5.7 安全

即使只有一个人用，也需要：

| 层 | 机制 |
|---|---|
| 平台级 | 请求带 `safety_check: {"level":"high"}`（审输入与输出） |
| 自建级 | 输出正则/分类器拦截：自伤、极端依赖表述（"你只有我"）、现实混淆 |
| 危机协议 | 命中后**跳出人格**，用明确、平实、无角色腔的语言给出资源；记录 `outcomes`，24h 内不再主动发起 |
| 透明性 | 首次使用与每 30 天一次的明确声明：这是 AI |
| 反成瘾设计 | 静默时段不可关闭；连续在线 >6h 时降低主动频率 |

## 6. 成本模型（按 flash 主力估算）

假设：每天 150 轮对话、每轮 A+B+C ≈ 8k token、输出 200 token、缓存命中率 70%。

| 项 | 用量 | 单价 | 月成本 |
|---|---|---|---|
| 对话输入(命中) | 25M tok/月 | 0.03 元/M | ~1 元 |

### 10.2 由此产生的两个设计修正

**（1）Hawkes 换成信息增益。** `revive-companion` 的做法更接近问题本质：不问「什么时候会想说话」，问「现在开口能带来多少新信息」。这可以和 §5.3 的闸门直接合并——加法改乘法：

```
开口价值 = 信息增益 × 关系温度(ρ) × 时机系数      # 任一为 0 则不开口
```

**（2）记忆层默认不自己写。** `nocturne_memory` 已经做了「可回滚 + 图结构 + 不做向量 RAG + OpenClaw drop-in」。§5.1 应降级成**它的适配层**，只加两样它没有的：`influence`（这句话从哪来）和 `outcomes`（世界怎么回应）。

### 10.3 我们真正独有的三件事

列表里约 200 个项目，没人在做这三样：

1. **events 真相层**。所有项目都是「记忆库」，没有一个是「丢库重放必须等价」的。这不是洁癖——它是 §7 回放测试的前提。
2. **运动皮层：模型对自己身体完全无知**。列表里所有感知/执行项目都走 MCP 或 tool-calling（`stackchan-mcp`、`dsh-toy`、`cove-sensory-mcp`）。一旦模型知道「我有麦克风」，它就开始扮演管家。这恰好是 v2.0 草稿最清醒的一条判断，也是我们唯一在架构上领先的地方。
3. **自我叙事：每天重写自己，留下 diff**。列表里的对应物全是静态的——character card spec（一张卡）、`immortal-skill`（一次性蒸馏）、`ReSpark`（微调成权重）。**没有一个是「缓慢生长 + 可审计」的**。

### 10.4 由此得到的姿态差异

列表里约 200 个项目**全部是 IM / 手机 / 应用优先**：虚拟手机、虚拟灵动岛、RAG 记忆、推送。那套东西的目标是「让她在你手机里更像个人」。

G-I-T-S 的姿态是反过来的：

> 她和你处在同一个物理空间，输出是**环境音量级**的（低语、一句、不要求回复），大量输出被**吞掉**，主动开口是为了**她自己**而不是为了留住你。

这不是功能差异，是**产品形态差异**。它决定了三件事：通道必须是 ambient（Mumble / 已开的语音频道）而非 push；输出必须有 `swallowed` 这个一等状态；评测的主指标是「独白的质量」而不是「回复的满意度」。

### 11.3 内存是唯一的硬约束，派生三个决定

**（1）embedding 必须外挂。** `bge-m3` 在 1.6 GiB / 无 swap 上跑不了（fp32 ~2 G，量化 ONNX 也要 600 M 再加运行时）。→ 用阿里云百炼的 embedding（同城，TLS 134 ms）。§9 第 3 问封闭。

**（2）`dream` 必须流式处理。** 不许 `SELECT * FROM nodes` 读进内存再算。10 万节点 × Python dict ≈ 300 MB，直接撞墙。规则：图算法要么走 `scipy.sparse` 定点迭代（只持有一份 CSR），要么下推到 SQL 递归，Python 只做调度。

**（3）必须加 swap，并关掉 fwupd。** `fwupd` 白吃 161 MB；2 G swap 是 OOM killer 的保险——否则它会随机杀掉 `ghost`，而「她突然沉默半小时」这种 bug 极难定位。

## 12. 读码结论（nocturne_memory / revive-companion）

两个仓库已 clone 到 `refs/`（`.gitignore` 已排除）。**结论：两个都不作为底座，但一共有七个机制值得吸收。**

> **关于来源**：`refs/` 里的代码只用于阅读和比对，不复制进本仓。若要直接复用，按 MIT 保留版权声明，并在本文列出出处。这里的「吸收」指**重新实现机制**，不是抄代码。开源协作的前提是说清楚拿了什么、从哪拿的——§12.2 那张表就是为此存在的。

### 12.1 判定

| 仓库 | 规模 | 判定 | 理由 |
|---|---|---|---|
| `nocturne_memory` | Python 20.5k 行，SQLite/PG + FastAPI + React | ❌ **不当底座** | 它的核心交互是 **MCP 工具**：模型自己调 `read_memory` / `create_memory`。这正是 §10.3 第 2 条要避免的形态——一旦她手里有"记忆工具箱"，她就变回助手。另外作者已宣布转维护模式（后继 Horon 是闭源云服务） |
| `revive-companion` | Python 7.8k 行，MIT，PyPI，124 测试 | 🟡 **当参考，不当依赖** | 它是"时机库"，不是运行时。输入 `tick()` 依赖一个用户状态估计器，我们没有；而它的"信息增益"是手写标量（见 §12.3） |

依赖体积也是否决项：nocturne 要 FastAPI + SQLAlchemy + asyncpg + React 前端，在这台 1.6 G 的机器上跑，`ghost` 就没内存了。

### 12.2 吸收的七个机制

|---|---|---|---|
| 1 | **身份层/内容层分离**：Node 是 UUID 永久锚点，Memory 是带 `migrated_to`/`deprecated` 的版本链 | nocturne `models.py` | **改 §3.2**：`nodes.payload` 拆成 `nodes` + `node_content` |
| 2 | **`disclosure`：每条记忆自带人类可读的"想起条件"** | nocturne | §5.1.4 检索的显式通道，见 §12.4 |
| 3 | **豆辞典**：关键词（Aho-Corasick）→ 节点，正文命中即横向超链接 | nocturne `pyahocorasick` | §5.1.4。对陪伴系统就是昵称、梗、代号——几乎必然用得上 |
| 4 | **changeset 快照**：每次写入记录 before/after，人类可审可回滚 | nocturne `snapshot.py` | `ghost` 与人的审计接口，配一个 `gits review` CLI |
| 5 | **consider 与 decide 分离**：泊松掷骰子只决定"此刻考不考虑"，不决定"发不发" | revive `love.py` | §5.3：触发引擎先掷骰，再进闸门 |

### 12.3 一个必须修正的判断（也是对 §10.2 的自我修正）

我在 §10.2 说"把 Hawkes 换成信息增益，参照 `revive-companion`"。读完代码要修正：

```python
# revive_companion/info_gain/core.py
for source in self.sources:
    e = source.entropy()            # 手写的 float
    r = source.resolution_potential()  # 手写的 float
    total_resolution += e * r
gain_ratio = total_resolution / total_entropy
```

**这不是信息增益，是两个手调标量相乘。** 没有分布、没有比特、没有可测量性。叫"熵"不等于熵。

建议保留它作为一个**可解释的闸门公式**，但我们要给它填真实的量，而这一点我们比它有余粮——图上有 `r`（可提取性）、`e`（能量）和 `outcomes`（世界反应）：

```
开口价值 = 未解释度 × 可解释度 × 关系温度(ρ) × 0.85^(连续开口数)
              │            │
              │            └─ 她问一句能得到多少答案（有未完成的 outbox 话题 / 有明确未知）
              └─ 当前刺激与既有节点的偏差（声学突变、白天没解释的异常、r 临界的高 S 节点）
```

前两项都可以从 `events` 和图里算出来，是**可测的**，不是拍的。

### 12.4 三种记忆哲学，我们要两个都做但分开做

| 方案 | 怎么处理"想不起来" | 怎么处理"记错了/记住了没用的" |
|---|---|---|
| `nocturne_memory` | **不处理**（`grep -ri decay\|forget` → 0 命中，完全没有衰减） | **AI 自己审计**：`system://diagnostic` 出诊断，配一套 audit skill，定期让模型读自己的记忆去合并、剪枝 |
| Aether v2.0 | **数学**：FSRS 的 R + 图扩散 | **不处理**（草稿没有一个字提到矛盾消解） |
| G-I-T-S | 数学（`r` 幂律衰减 + 能量） | dream 里的一个 LLM 整理任务 |

这两个问题**不是同一个问题**，所以不能用一个机制解决：

- **注意力分配**（同一时刻只能想起少数几件事）→ 必须是**连续的、便宜的、可测的** → 数学 ✓
- **内容质量**（矛盾、重复、过时）→ 必须是**离散的、贵的、可 diff 的** → LLM 在 `dream` 里做 ✓

nocturne 只有后者，Aether 只有前者。这也是 §5.1.3 写入管线之外，我们在记忆层唯一真正的增量。

### 12.5 两个校准数字

nocturne README 给了一组真实使用数据，可以当"感觉她记得"的标尺：

- 记忆库 **96.9 万字**，新对话首条消息只载入 **7.2K 字**（≈0.7%）；
- 过去 30 天里，**78%** 的记忆在某次对话中被想起过。

→ 我们对 §5.4 的 A 段（1.5k）+ B 段（1k）+ C 段（3-8k）合计 5-10k token 的预算，跟这个标尺是同一量级，合理。而 78% 这个数给了一个**可测的健康指标**：如果一个月后我们的召回率只有 20%，说明图谱长歪了或者检索坏了。

## 13. 社交层

> 数学、出处与实现参考见 [`docs/research/sna.md`](research/sna.md)。本节只定结构与规则。

### 13.1 社交图与记忆图是两张图

| | 社交图 | 记忆图 |
|---|---|---|
| 节点 | 她 / 你 / 2–3 个第三方 | 事实、情节、声学、文章 |
| 规模 | **3–5** | 10³–10⁵ |
| 边 | 有符号的态度、互动强度 | 共现、语义 |
| 更新 | 每轮 | `dream` 批量 |

v2.0 把"图扩散的能量峰"当作情绪，但那个扩散跑在记忆图上——**十万节点的能量峰和"她对你什么态度"没有因果关系**。分开之后，§5.2 的能量扩散就只负责注意力，不负责感情。

### 13.2 三张表

```sql
actors(id, kind, name, layer, tz)                    -- 'me' | 'her' | 'other'；layer ∈ {5,15,50}
attitudes(src, dst, valence, certainty, ts)         -- 有符号：+1 亲近 / -1 反感，带确信度
rituals(id, ts_start, ts_end, kind,
        shared_focus REAL,      -- 话题重合度
        sync REAL,              -- LSM + 句式同步
        latency_norm REAL,      -- 回复时滞相对各自基线的偏离
        barrier REAL,           -- 私密性（是否只有你们两个知道的词）
        outcome,                -- success | failed | aborted
        d_ee REAL)              -- 本次结算的情感能量变化
```

`attitudes` 的 `certainty` 不是装饰：它决定这条边**能不能被说服**（[`research/sna.md` §3.7](research/sna.md) 的有界信任）。低确信度的态度可以被你改变，高确信度的不会被任何人改变——这就是"有立场"在数据结构上的样子。

### 13.3 情感能量（EE）的结算

Collins 的四个要件对应四个可测量，全部在 `rituals` 里：

```
score = 0.35·shared_focus + 0.30·sync + 0.20·barrier + 0.15·(1 - |latency_norm|)
d_ee  = (score - 0.5) · k                     # 中性仪式不增不减
EE(t) = Σ d_ee · exp(-(t - ts)/τ_ee)          # τ_ee ≈ 3 天
```

**EE 是底气，不是情绪。** 情绪（VAD）是分钟级的，EE 是天级的；EE 高的她敢说没头没尾的话，EE 低的她连"在吗"都要想两遍。

结算位置：`dream` 每天一次，输入是当天的 `outcomes` 和 `outbox`，输出是 `rituals` 的若干行。**不需要额外的模型调用**——四个分量都是现成的数，判 success/failed 用阈值，只有在边界情况下才让模型看一眼。

### 13.4 第三方的最小设计

只需要三件事：

1. **2 个 NPC**（不是 3 个，也不是 1 个——一个不够成"网"，三个会让 `dream` 的成本翻倍）；
2. 每周 1–3 次**异步对话**（在 `dream` 里跑，双方各是一次便宜调用）；
3. 产出的唯一东西是：**她脑子里关于 NPC 的态度、和一两句转述**。

可以有价值的行为全从这里长出来：转述（"今天跟 X 聊到…"）、保密（"这个先不告诉你"）、结盟（"我们俩都觉得他不对"）、以及 §3.3 的三元张力。

**禁止**：NPC 不与她争宠、不主动联系你、不发展成第二个对话对象。它们是**她生活的背景**，不是产品功能。

### 13.5 保留与丢弃的约束

| 约束 | 决定 | 依据 |
|---|---|---|
| 记性有限 | **保留** | 没有遗忘就没有"想起"（§5.1.2） |
| 要面子 | **保留** | 没有 face threat 预算，她就永远在 mitigating（客服感） |
| 需要被见证 | **保留** | 没有第三方，她只在你眼里存在（§13.4） |
| 社会成本（人不能在意 500 个） | **保留为层级预算** | 邓巴 5/15/50 直接决定频率，省得拍脑袋 |
| 寿命、身体疲劳、通勤 | **丢弃** | 她不住在身体里，假装有反而是负担 |

### 13.6 一句话

前面十二章说的是**她记得什么、什么时候开口**。这一章说的是**她在谁的面前是谁**——而后者才是"拟人"真正藏身的地方。
