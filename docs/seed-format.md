# 初始化包（gits-seed/1）

> 给**机器生成、人不看内容**的初始状态用。
>
> 三条原则：
>
> - **只解析，不入库文件本身**——导入之后状态只在事件里，文件留在仓库外面
> - **先校验，再写**——默认 dry-run，任何一条不合法就整份拒绝（不跳过坏的）
> - **报告不回显正文**——错误只说位置、字段、数值范围

## 1. 为什么体裁限制得这么死

只允许三样东西：**实例身份、自我描述、注意力偏好**。

不允许塞 `msg_in` / `inner` / 任何带时间戳的事件。理由：

节律、遗忘、复现次数全是从**活动历史**里学出来的。
一次假导入会让漏斗以为某个话题被反复提起过，让节律以为某个时段很活跃——
**污染一整个月，而且查不出来**（数据看起来完全正常）。

格式里没有事件，这件事就没法发生。

## 2. 格式

```json
{
  "_comment": "以 _ 开头的键当注释，导入时忽略",
  "format": "gits-seed/1",
  "generated_at": 1800000000000,
  "actors": [
    {
      "id": "her",
      "main": true,
      "persona": "一段第一人称的自我描述",
      "topics": { "开会": 1.2, "咖啡": 0.8 }
    },
    { "id": "peer1", "main": false, "persona": "…", "topics": {} }
  ]
}
```

| 字段 | 约束 |
|---|---|
| `format` | 必须是 `gits-seed/1` |
| `actors` | 1..8 个；`id` 小写字母开头 2..32 位；不能重复 |
| `main` | **有且只有一个** true |
| `persona` | 非空，≤ 2000 字 |
| `topics` | ≤ 32 个；名字 ≤ 24 字且无控制字符；权重 ∈ [0.1, 5.0] |
| 文件 | ≤ 64 KB，无 NUL 字节 |
| 未知字段 | **拒绝**（打错字不该被静默忽略） |

模板在 `docs/seed-template.json`，它自己也是测试用例（必须能过校验）。

## 3. 用法

```bash
gits import-seed /path/to/seed.json          # 只校验，打印结构摘要
gits import-seed /path/to/seed.json --write  # 真的写
gits replay --restore                        # 让投影跟上
```

校验输出长这样（**没有正文**）：

```
格式 ok（gits-seed/1），摘要 b73a90d766872154
实例 3 个：
  her（主）  自我描述 29 字  偏好 咖啡=0.8、开会=1.2
  peer1  自我描述 11 字  偏好 论文=1.1
  peer2  自我描述 11 字  偏好 无
```

## 4. 三个实现上的决定

**① 文件不能放在仓库里。**
`inside_repo()` 会拒绝——她读不到 `/srv/gits`，但仓库会被 push 到公开远端。

**② 幂等键是整份内容的哈希。**
`seed-{actor}-{digest}`，重导同一份不会重复。换一点点内容就是新的一份
（因为它们本来就不同）。

**③ 写进去的还是普通事件。**
`source='seed'`、`kind='seed'`，和夜里自己写的人格快照走同一条重放路径。
所以它会衰减、会被顶掉、会被压进摘要，`gits wipe` 能清掉。

## 5. 还没做的

- **关系**：格式里没有。按设计 peer 之间初始无关系，
  「认识」应当是发生的，不是写进去的。
- **口令/加密**：文件是明文 JSON。它不在仓库里，但也不加密。
  如果生成它的机器不可信，那是另一个问题。
- **增量导入**：现在是一整份；换一份就有两套种子（旧的那条还在，会衰减）。
  真要替换得先 `wipe`。
