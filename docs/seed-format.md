# 初始化包（gits-seed/1）

> 给**机器生成、人不看内容**的初始状态用。
>
> 三条原则：
>
> - **只解析，不入库文件本身**——导入之后状态只在事件里，文件留在仓库外面
> - **先校验，再写**——默认 dry-run，任何一条不合法就整份拒绝（不跳过坏的）
> - **报告不回显正文，连话题名都不给**——错误只说位置、字段、数值范围

## 1. 为什么体裁限制得这么死

只允许五样东西：**实例身份、自我描述、注意力偏好、角色事实、关系前史**。

不允许塞 `msg_in` / `inner` / 任何带时间戳的事件。理由：

节律、遗忘、复现次数全是从**活动历史**里学出来的。
一次假导入会让漏斗以为某个话题被反复提起过，让节律以为某个时段很活跃——
**污染一整个月，而且查不出来**（数据看起来完全正常）。

后两样能进来，是因为它们**不伪造活动历史**：角色事实是一组可核对的数值，
前史是一条标注为"导入"的基线。它们既不产生活动，也不冒充交互。

格式里没有事件，这件事就没法发生。

## 2. 格式

```json
{
  "_comment": "以 _ 开头的键当注释，导入时忽略",
  "format": "gits-seed/1",
  "generated_at": 1800000000000,
  "ephemeral": true,
  "character": {
    "birth_date": "1999-11-30",
    "height_cm": 165,
    "weight_kg": 52,
    "bust_cm": 86,
    "underbust_cm": 75,
    "waist_cm": 62,
    "hip_cm": 90,
    "shoulder_cm": 38,
    "inseam_cm": 78,
    "foot_cm": 23.5
  },
  "relations": { "body_count": 0 },
  "actors": [
    {
      "id": "her",
      "main": true,
      "persona": "一段第一人称的自我描述",
      "topics": { "开会": 1.2, "咖啡": 0.8 }
    },
    { "id": "peer1", "main": false, "persona": "…", "topics": {} }
  ],
  "facts": [
    {
      "subject": "him", "key": "birthday", "label": "他的生日",
      "month": 3, "day": 12, "lead_days": 3, "repeat": "yearly"
    }
  ]
}
```

### character：只放可测量的

键必须落在 `character.ALLOWED` 里——身高、体重、三围、下胸围、肩宽、内缝长、脚长、生日。
血型、色觉、性别不在里面：它们不是"会变的状态"，是不该被模型改写的记录。

年龄**不写**，由 `birth_date` 读时推导。

**导入是唯一一次能塞进一整组数字的地方，所以跨字段自洽检查在这里跑**
（BMI、腰臀比、胸围差、各部位与身高之比）。`character.bounded()` 管的是
"一周变了多少"，导入没有"上一周"，跑不了。

任何一条不成立，整份拒收——不是"跳过坏的那一项"。理由和别处一样：
一个荒唐的数字夹在那里，之后每次读都会把它当真。

### relations：只收数不出来的

```json
{ "body_count": 0, "first_time": "2019-06-01" }
```

就这两项。之后发生的事由 `kind='relation'` 事件累积（`gits relation kiss` 那样一次一条），
**不接受在这里预置**——那等于凭空造一段没发生过的历史。

两项都有跨字段校验：

- `first_time` 不能在未来
- 不能早于 `birth_date`
- 对应的年龄小于 12 岁 → 拒收（**笔误拦截**：`2015` 少打一位就是这种错法）

## 3. 用法

```bash
# 1. 先 dry-run。报告不给数值、不给话题名
gits import-seed /path/outside/repo.json

# 2. 真写
gits import-seed /path/outside/repo.json --write

# 3. A 段是空的就重建投影
gits replay --restore
```

示例包（`ephemeral: true`）生产默认拒收，要导得加 `--allow-ephemeral`。
文件必须在仓库外面：**文件不进来，状态才进来。**

## 4. 三个实现上的决定

**整份拒绝，不跳过。**跳过意味着"这份文件部分可信"，而校验报告只说位置——
人看不出被跳过的是什么，也就没法判断该不该重做。

**报告不回显正文。**话题名也是内容：随机抽到「深海热泉」「编译原理」，
跑一次 dry-run 就把核心关注点全剧透了，blind 就白设了。
默认只给数量与权重和，要看名字得显式 `--inspect`。角色事实同理——只报几项，不报数值。

**幂等靠内容哈希。**`ext_id` 里带整份文件的摘要，重导同一份不会重复写。

## 5. 还没做的

- **月历只支持阳历。**lunar 明确拒绝，不猜——猜错一次会在错误的那天祝人，比忘记更糟。
- **导入不检查"她几岁"和身高的匹配**：`birth_date` 和身高各自合法就够了。
  一个 12 岁 165cm 是可能的（早发育），拦它会把正常情况也拦掉。
- **前史没有来源字段。**写进去之后就是基线，追不到"谁说的"。
  现在只有一个使用者，这不是问题；多人的话要加。
