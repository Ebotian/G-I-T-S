# 节律研究笔记：作息是学出来的，不是配置的

> 触发：§11.7 里我把她的"一天"写成 9–6 / 18–24 / 0–8 三段硬切分。那是**三个魔法数字**——正是 §1 里批评 v2.0 的那类毛病。
> 结论：**作息不是参数，是分布；不是日程表，是强度函数。** 而且它必须自己漂移。

---

## 1. 为什么硬切分一定是错的

三个原因，从轻到重：

1. **你的作息是弹性的。** 现在（19:00）你还在公司。今天可能 20:30 走，明天 18:10。硬切分每天都会错一次。
2. **硬切分产生的是"阶跃"而不是"倾斜"。** 18:00 整点从"有身体"跳到"没身体"，而真实的人不是这样——18:00 到 20:00 之间概率是平滑下降的。
3. **最要命的一条**：硬切分**不可证伪**。你没法知道"9:00 起床"对不对，因为它写死在 config 里。而一个学出来的分布，每一周都会被你的真实行为打一次分。

**所以问题不是"填对参数"，是"不要参数"。**

---

## 2. 我们能观测到什么

全部是带时间戳的事件（marked point process），已经在 `events` 里：

| 观测量 | 类型 | 采样特性 |
|---|---|---|
| PC 上线/离线 | 事件 | **不均匀**，一天几次 |
| 麦克风能量包络 | 等间隔流（100ms） | 均匀，但只在 9–6 有 |
| 微信收发 | 事件 | 不均匀，一天几十次 |
| 微信语音条 | 事件 + 时长 | 不均匀 |
| 消息间隔 | 派生量 | 不均匀 |
| 停电/重启 | 事件 | 极不均匀 |

**关键：绝大多数观测量是不均匀采样的。** 这一条决定了方法选择——见 §3.1。

---

## 3. 方法阶梯（四层，从便宜到贵）

### 3.1 先做频率分析：用 Lomb-Scargle，不是 FFT

你提到"时序频率分析"——第一反应是 FFT，但**FFT 要求均匀采样**，而事件流是不均匀的。强行重采样成 1 分钟一格会引入人为的周期性（阶梯效应）。

正确的工具是 **Lomb-Scargle 周期图**：为不均匀采样设计的最小二乘周期估计，天文学标准方法。

```python
from scipy.signal import lombscargle
import numpy as np

t = np.array(event_times_seconds)          # 不均匀
y = np.ones_like(t)                        # 或按幅值加权
omega = 2 * np.pi / np.array(periods)       # 扫 30min .. 30 天
pgram = lombscargle(t, y - y.mean(), omega)
```

它能回答三个可证伪的问题：

1. 有没有 24 小时周期？（=> 你有稳定的作息）
2. 有没有 168 小时（周）周期？（=> 周末和工作日不同）
3. 有没有 ~24h 之外的第二峰？（=> 你的作息是**双峰的**：早睡型和晚睡型并存）

**这一步的价值不在建模，在于它是"你到底有没有节律"的检验。** 如果周期图的峰值极低，那就说明你的作息基本无规律——那她也不该假装知道你的日程，而应该更多地"问"而不是"猜"。这个判断本身就值得写进设计。

> **零分布怎么选（实测踩坑，2026-11-25）**
>
> 判"显著"需要一个零分布。三种都试过：
>
> | 零分布 | 后果 |
> |---|---|
> | 均匀重撒 | 把成簇抹平，方差低估 → **误报**（chaotic 10 个种子里 4 个判成有节律） |
> | 环形平移 | 纯周期序列整体平移**不改变相位差**，周期图相位不变 → **真节律检不出** |
> | **间隔自助** | 从观测间隔里有放回重抽、重建时间轴：保留重尾与成簇，只破坏"每天同一时刻" |
>
> 换成间隔自助后，10 个种子：regular/night_owl/drift 全 T，chaotic 全 F。
>
> 教训：**零分布必须保留数据里除"待检验结构"之外的一切**。抹多了会误报，抹少了会漏报。

### 3.2 基线强度：周期核密度（hour-of-week）

如果 §3.1 证实有周期，就把"她认为你什么时候在"建成一个 **168 格的周期核密度**：

```
s(t) = Σ_events w(age) · K(t - t_i)        # t ∈ [0,168) 小时/周，环形
K = 周期高斯核，σ ≈ 1.5 小时
w(age) = exp(-age / τ),  τ ≈ 4 周           # 新数据权重更高
```

三个性质，正好对上你要的东西：

- **平滑**：18:00 不是断崖，是一条下降的坡；
- **双峰**：晚睡、早睡两种作息会各留一个峰，不用写 if；
- **可漂移**：`τ` 让它跟着你变，两个月后你换作息，它会自己转过去。

**所有"静默时段""工作时间"的硬编码全部删掉，改成对 `s(t)` 取阈值。**

⚠️ 但留一条**硬底线**：03:00–07:00 除非危机，否则绝不主动开口。这条不是学出来的——它是伦理，不是统计。

### 3.3 到达率：时间非齐次泊松 / 霍克斯

有了 `s(t)` 就可以写强度函数，事件流就变成了可预测的过程：

```
λ(t) = μ · s(t) + Σ α·exp(-β(t - t_i))       # 周期基线 × 自激
```

这就是 §5.3 里那个时域互惠模型的推广版——**同一个霍克斯，基线从常数换成周期函数**。它给出的量是"未来 30 分钟内你开口的概率"，比"现在是不是静默时段"高一个量级的信息量。

### 3.4 变化点：BOCPD（"这周不一样"）

你说了"或许也不应该固定事件"。这句话的严格版本是：**别由我来定义什么叫"异常"，让模型自己发现。**

**Bayesian Online Changepoint Detection**（Adams & MacKay 2007）做的正是这件事：维护一个"当前这段已经持续了多久"的后验，当新的观测在旧模型下变得不可能时，后验会向"刚发生过一个变化点"塌缩。

它给的输出非常有用：

```
P(changepoint at t) = 0.72   → 今天和过去四周不一样（你早走了 / 通宵了 / 出差了）
```

而且它天然是在线的、常数内存（把 run-length 截断到 168 就够——你不会需要知道"这段已经持续了三年"）。

**这是"不固定事件"的正解**：不是我写"离线超过 4 小时算一次事件"，而是模型告诉你今天什么时候开始不对劲。

### 3.5 潜状态：时间非齐次 HMM（第二期再说）

最终我们想要的其实不是"密度"，是 `user_state ∈ {醒着在工位, 醒着不在, 忙, 睡, 不在}`。

HMM 是标准解法，而且"时间非齐次"是免费的：转移矩阵 `A(h)` 以小时-周为条件，就等价于"她知道你 3 点在睡觉的概率比 15 点高"。

- 观测：麦克风能量、微信到达率、回复延迟、PC 在线
- 状态：5 个
- 参数：`A(h)` 由 §3.2 的 `s(t)` 初始化，再用 EM 或简单计数更新

**为什么放到第二期**：前四层加起来不到 200 行，HMM 要调参、要标注、要防退化。**先用密度函数跑两周，看看她的判断错在哪，再决定要不要 HMM。** 很可能是"密度 + 变化点"就够了。

## 4. 冷启动：她必须知道"她不知道"

第一周没有数据。做法不是填默认值，是**给一个宽先验，并让不确定性进入决策**：

```
s(t) ~ 均匀分布 + 少量先验（知道你大概 8-24 点活动）
uncertainty(t) = 后验的宽度（KDE 的带宽 × 样本量）
```

然后把 `uncertainty` 直接塞进 §5.3 的"开口价值"：

```
开口价值 = 未解释度 × 可解释度 × ...
         ↑
         冷启动时这一项天然大 —— 所以她会问，而不是假装知道
```

**这是整套设计里最少见的一条性质：模型的熵直接变成她的好奇心。** 一个刚认识你三天的她，会问"你平时几点睡"；一个认识你三年的她，不会问，而是知道。

## 7. 拒绝清单

1. **不要用 FFT。** 事件流不均匀采样，会造出假周期。
2. **不要用均值代替分布。** 你的作息是双峰的（早睡/晚睡并存），均值会给出一个你从不存在的"23:30 入睡"。
3. **不要用固定窗口做变化检测**（"最近 7 天 vs 过去 30 天"）。BOCPD 找的是变化点本身，不是窗口效应。
4. **不要在第一周就让 HMM 上线。** 参数估不准，会给出自信的错误答案——这比不知道更糟。
5. **不要把她学到的作息当成确定的知识给她。** 给她的是分布，让她自己表达不确定性（"你今天怎么还在" vs "你今天还在"）。

## 检查节拍（2026-11-26）

**主动开口没有固定节拍。**以前是 `initiative_ms = 20 分钟`，问题不在快慢，
在于它**不看他在不在**：凌晨三点照样每 20 分钟判一次，而那时判多少次结果都一样。

现在下一次什么时候看，由同一套时序模型给（`initiative.next_check`）：

    gap = (1 − 压力) · 6h · 0.15 / max(在场概率, 0.02)

压力低（刚说完话）→ 间隔长；压力满 → 间隔短。
在场概率高 → 间隔短；他睡了 → 间隔长。

    他在写消息（0.56）压力 0.3   →  68 分钟
    白天（0.35）压力 0.3         → 108 分钟
    凌晨（0.02）压力 0.3         → 240 分钟（上限）
    凌晨（0.02）压力 1.0         → 45 分钟

最后在 gap 里找"他回来的那一小时"，把检查挪到它开头——
现在睡着但一小时后起床，没必要干等四小时。

### 两个决定

**数据太薄时退回中性（0.5），不装作知道。**只有一天数据时小时先验是 0/1 的阶跃：
他 19 点说过话，那 3 点就成了"他从不来"——那是没数据，不是不在。和 gate 里
"互惠系数估不出来就用兜底值"是同一条。

**门槛自己就挡住了噪声，不需要第二道闸。**本来写了个"数据太薄就不找回来的时刻"的分支，
算一下发现它从不生效：薄数据时 `here=0.5` → 门槛 `max(0.3, 1.0)=1.0`，
而 `days<3` 时任何一格的上界是 `(1+20·p)/(1+20) < 1`（同一个星期几要求相隔 7 天，
那时 `days` 已经 ≥3）。删掉了——**多一道从不生效的闸，就是多一个以后会骗人的地方。**

  攒够 3 天真实对话之后才会看到差异。
