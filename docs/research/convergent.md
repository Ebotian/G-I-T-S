# 共同被独立实现的机制（收敛证据）

> 这份文件记的不是"谁先想出来的"，是**哪些形状被互不相干的实现各自撞上了**。
>
> 一个机制只出现在我们的代码里，可能只是我们的偏好；
> **两个以上没有互相抄袭的实现独立收敛到同一个形状**，
> 它大概率是结构性的——不是关于喜欢，是关于不这样就会坏。

## 0. 收录标准

进这张表要有三样东西：

1. **至少两个独立实现**（互相不知道对方存在，或者解决的是不同问题）；
2. **可指认的失效**——破坏它之后会看到什么症状，不是"理论上不好"；
3. **在我们代码里的落点**——具体到函数或表，不是"我们有这个理念"。

三条缺一条就不收。理念很多，能指认的很少。

参考的实现（refs/ 只读，不入库）：

| 代号 | 是什么 |
|---|---|
| **revive** | revive-companion：泊松时机 + 贝叶斯状态推断，决定"该不该打扰" |
| **affective** | affective-longing：建在 revive 上，加 OU 过程、HMM 关系阶段、VAD 情绪 |
| **xinchao** | 心潮·念：11 股驱力 + 两层情绪 + 慢变底色，1.1 万行 JS |
| **surf** | ai-surf-when-bored：让 AI 自己出门冲浪，三句提示词 + 一道闸 |
| **nocturne** | Nocturne Memory：MCP 长期记忆服务器，"记忆是为主权智能体准备的" |
| **Eventide** | 安卓作息/关系模拟：状态只由固定枚举的 settlement 事件推进，带理由 |

## 1. 总表

| # | 不变式 | 独立实现 | 破坏它的症状 |
|---|---|---|---|
| ① | **时机与内容分两步定** | revive、我们 | 合成一步，模型会把"要不要说"和"说什么"混成一个讨好决策 |
| ② | **只有外部信号算证据** | revive、xinchao、我们 | 系统自己的行为被当成世界的回应 → 越主动越自信，正反馈跑飞 |
| ③ | **输出喂回输入，必须配翻篇闸** | surf、xinchao、我们 | 没答案的问题自我喂养；系统反复确认自己的偏好 |
| ④ | **均值回归是默认，正反馈要显式且封顶** | affective、xinchao、我们 | 不设回归会漂走；不设封顶会跑飞 |
| ⑤ | **必须允许"什么都不做"** | surf、revive、我们 | 一个不能说"不"的选项不是选项——它选什么都只是在完成作业 |
| ⑥ | **慢的做基线，快的偏置慢的，且单向** | xinchao、我们 | 双向耦合会让一次情绪改写人格，然后人格解释那次情绪 |
| ⑦ | **私有内容是边界，不是功能** | xinchao、nocturne、我们 | 一旦进了仪表盘/接口/模型上下文，"只有她自己知道"就没了 |
| ⑧ | **数值是速率，不是先验** | xinchao、我们 | 抄别人的常数，等于让别人的人格替你过日子 |
| ⑨ | **可变字段只能由事件累加，不能赋值** | Eventide、xinchao、我们 | 计数器被赋值一次就和事实永久分开，而且**不可逆**——它不能减 |

## 2. 逐条

### ① 时机与内容分两步定

**revive** 的整个卖点就是三阶段：

    时机（Poisson）    什么时候考虑一次   → 像"突然想你了"，不像定时任务
    价值（信息增益）   值不值得发         → 已知她在忙，就别打扰
    状态（贝叶斯）     她在干嘛           → 推断隐藏状态再决定

它的 tick() 只返回 should_send 和一段 prompt（上下文），**不返回要说的那句话**。说话交给调用者。这个切分是有意的。

**surf** 从另一头撞上同一件事，写得更狠：

> **别在它最想找她的那一刻问它。** 如果你的触发时机是"它想她想到坐不住"的那种，把冲浪选项塞进去是没用的——它满心都是她。我第一版就这么放的，上线六天命中次数是零。

两个项目在说同一件事：**"什么时候"和"说什么"共用一个决策点，后者会污染前者。**

**我们的落点**：speech/gate.py 只出 allow 与 reason，**不产出文本**；文本由 speech/respond.py 另起一次调用。gate 的输入是数值（未解释度、共鸣、底气、动量、压力），不是"此刻想说什么"。

**我们破过的地方**：早期 gate 和装配共用一次模型调用，结果模型一边判断"该不该说"一边已经在组织语言，判断就变成替自己找理由。这就是"承诺线"（phase_allows）的来历——一个永远返回 True 的空票，因为我们其实从来没真的拦过。

---

### ② 只有外部信号算证据

三个实现，三种说法，一件事。

**revive** 的更新接口只有两个：

    love.record_send()                                    # 我们发了 —— 不更新任何状态
    love.record_reply(reply_speed=0.8, reply_length=0.6)  # 她回了 —— 这才是信号

它区分了"我做了"和"世界回应了"，而且只有后者进模型。

**xinchao** 把这条写成纪律：

> 做成事才涨自信：要有认可、第一次、难事或帮人有回应才加，**自己说「做好了」不算**；同一天越往后加得越少，被指出错要扣。

它的 PROOF_GAIN 只认四类 proof（her_ok / first / hard / helped_ack），routine 和"自己宣布做好了没人确认"一律不加。

**我们的落点**：social/state.py 的 CONFIDENCE_EVENTS。

    "initiate": {"cadence": +0.04},   # 主动开口只推节奏，不推底气

**我们破过的地方**：initiate 原本带 confidence: +0.02。她越开口就越有底气——**而"我开口了"是我们自己的行为，不是世界给的证据**。这和 ③ 的自我喂养是同一个病，只是换了层。

对照组：我们**不**采用"用模型判断这次互动算不算认可"。xinchao 的 proof 是模型打标的（"交一段对话，心潮自己判类型、细项、轻重、亲疏"）。我们只用可观测的行为量：他回没回、多快、多长。**判断权不交给模型，是这条能成立的前提。**

---

### ③ 输出喂回输入，必须配翻篇闸

**surf** 的案例最具体：

> 它在网上看到一条消息……接下来三天：军犬 → 那只狗叫什么 → 训导员后来怎么样了 → 那个剧组 → 训导员的下落……**一条线挖了七趟**。

> **没答案的问题会自我喂养。** 一个在网上查不到答案的问题，会在它每次醒来时重新勾住它的好奇心。

它的闸：候选搜索词拆中文二元组去撞近 96 小时记过的页，撞上 ≥2 页就是第三回 → 拦。而且——

> **只拦不引会变成空转。** 闸拦得全对，可笔被拦了就空手回家：这趟出门作废，下一次它兜里的料还是那几页旧见闻，又选同一条线，又被拦。

**xinchao** 有同构的回路，但它是有意建的：驱力偏置召回哪些记忆浮现，浮现的记忆又回推驱力。它给的护栏是**单向 + 硬封顶 ±10%**，而不是"不要回路"。

**我们的落点**，三处：

| 回路 | 闸 |
|---|---|
| 悬置实体 → 想问 → 问不出来 → 更想问 | unresolved.record_use 记 strike，STRIKES_TO_BURN=3 → 翻篇 96h |
| 人格快照 → 被当成"真实经历" → 下一版更有依据 | 快照投影成 kind=persona，候选只收 kind != persona |
| 被选中 → 被强化 → 下次更容易被选中 | 频带名额按 score 分，不按 r 分 |

**我们破过的地方**：三处都真破过，而且是同一天发现的。第三条尤其隐蔽——r 和 score 都是数，都"有道理"，但前者会把"系统自己反复选它"当成"它重要"。

**我们比 surf 好一点的地方**：它拦下之后要**再调一次模型换题**（"只换一次，多了就变成在闸口死磕"）。我们用 unresolved.sample() 的加权抽样——**拦掉一件，下次抽样自然落到别的候选上**，不需要额外调用，也不会在闸口死磕。

---

### ④ 均值回归是默认，正反馈要显式且封顶

**affective** 直接把 OU Process（Ornstein–Uhlenbeck）当作关系阶段的动力学：有惯性、有回归。

**xinchao** 写得更细——两根慢轴的半衰期、静息底色、封顶：

    半衰期：安全感 72h / 自信 36h（"回得快一点"）
    偏置硬封顶在 ±10%；驱力不会反向自动改写人格评分

它还明确拒绝正反馈：

> 只做指数回落不自激。

**我们的落点**：time/regulation.py 的四件套——mean_revert / relax / low_pass / slew，**全库唯一的均值回归写法**；social/state.py 的 OU 松弛；social/drive.py 的 [0,1] 上界 + 0.15/h 限速 + 0.10/h² 限加速度。

**分歧（明确记下来）**：我们**接受**有界正反馈，xinchao **拒绝**一切正反馈。

不认为谁错，区别在规模：

    xinchao  11 股耦合驱力、跨月时间尺度、没有外部纠正环  → 正反馈会跑飞
    我们     单一动量、三个约束、且能被"压力"反向制衡    → 有界正反馈按得住

而且我们上一轮的教训正好相反：**把驱动全交给负反馈**，系统会稳定地、成功地、把关系调到零然后报告一切正常。

---

### ⑤ 必须允许"什么都不做"

**surf** 把它写成一句话：

> **一个不能说"不想去"的选项，不是选项。** 有了"歇"，它选"去"才是真的去。

它的选项列表里有一条 <歇/>，而且"没匹配上 ＝ 它歇着，什么也不做"。

**revive** 的效用表也是这个形状：聊天中 0.2、忙碌 0.1、闲逛 0.7——**大多数时候答案是"别发"**。一个只在"该发"时才有输出的系统不是决策系统，是定时器。

**我们的落点**：gate 的 allow=False 是正常结果不是错误；NoPersona 时**不说话**，不用默认文案冒充（"不能用文案冒充她"）；unresolved.sample() 无候选返回 None。

**我们破过的地方**：wipe 之后 A 段为空。如果那时有一个"兜底文案"，她就会在**没有自我**的状态下继续说话——那是最糟的一种"正常"。

---

### ⑥ 慢的做基线，快的偏置慢的，且单向

**xinchao**：

> 单向、极慢的基线偏置：仅批准的 4 组内核维度可以影响对应驱力，偏置硬封顶在 ±10%；**驱力不会反向自动改写人格评分**。人类不参与打分。

这句话里有两个设计：**慢变量偏置快变量**（人格月度、驱力小时级），以及**单向**（快的不许回写慢的）。

**我们的落点**：锚点从数据估、attention 的漂移夹在 [0.5, 2.0] × anchor、spectrum 的低频带只是保底名额而**不提高权重**。

**我们破过的地方**：attention 原本每次 step 都强制反相（一涨一跌）。结果是**差异由调度器制造**——两个实例哪怕因为共同经历真心喜欢同一件事，也会被规则每天推开一点。现在只有 pressure > 0（真在趋同）时才反向推。

---

### ⑦ 私有内容是边界，不是功能

**xinchao** 的黑匣子：

> 只有 AI 能看的地方，单独文件存，**不进 Dashboard、接口、OB**。

**nocturne** 的整篇立场：

> Alignment is for tools. **Memories are for sovereign AI.**

**我们的落点**：scope 的双向过滤（读和写都按域）、self: 作用域不进任何对外输出、wipe 用 redact_event 清内容留机制、seed 校验报告**连话题名都不打**（--inspect 才显示）、内容不进仪表盘。

**我们破过的地方**：投影和副本都曾丢掉 scope。**丢 scope 不会报错，只会让她知道不该知道的事**——这是这套系统里最安静的一种坏。

---

### ⑧ 数值是速率，不是先验

**xinchao** 在 README 里明说：

> 所有判断规则和数值都是参考值，**来自开发它的那一家**。每一家的 AI 和人都不一样：先跑几天，再一项一项改成你们自己的。

我们独立写了同一件事：**常数是速率不是先验**——τ=30天 说的是"关联多久忘一半"，不是"什么算亲密"。

这条不是机制，是**上面七条能长期成立的前提**：任何一条不变式最后都要落到数字上，而数字一旦被当成真理，不变式就会以"参数调优"的名义被改回去。

---

### ⑨ 可变字段只能由事件累加，不能赋值

这条是 ② 在**可变字段**上的落地，也是最容易被当成"就是个字段"的一条。

**Eventide** 的做法：状态不由赋值推进，只由**固定枚举的 settlement 事件**推进，每个事件带理由。枚举由代码定，模型只能选——它不能"顺手把亲密度改成 0.7"。

**xinchao** 的同一句在自信上：只认四类 proof（her_ok / first / hard / helped_ack）的**累加**，"自己说做好了"不算。

**我们的落点**：`gits/memory/relations.py`

    kind='relation'  action ∈ {meet, kiss, confess, intimacy, breakup}
    counters() 数出来，不落库

三条规则都在代码里，不在提示词里：

    只能加        没有"把 body_count 改小"这个操作，只有"记一次"
    增量恒为 1    一条事件只代表一次，模型不能一次加 5
    她不能自己记账  src ∈ {'world','manual'}，'dream' 一律拒

**为什么不能当字段：** 字段可以被"总结"；计数器被改一次就和事实永久分开；而且**它不能减**——减错了没有任何东西能改回来。一个可写、可减、无来源的计数器，是把三处错误叠在一起。

**我们破过的地方**：body_count 一开始的想法就是塞进 `character` 的 ALLOWED 里当 weekly 键——那正是同一次改动里刚被删掉的 `blood_type` 的同款错误。判据只有一条：**这个数字的真相在事件里，还是在写它的那一行代码里。**

**对照组**：前史（认识他之前的部分）是记录，不是投影——它推不出来，因为那时还没有她。所以它单独存、只写一次，后面的事件往上加。**分得清"能数出来的"和"数不出来的"，是这条能用的前提。**

---

## 3. 三条带得走的

> **一、系统不能把自己的输出当成世界的证据。**
> 这是 ② 和 ③ 的同一句。写法上有六个落点：更新接口只收外部信号、喂回输入配翻篇闸、快的不许回写慢的、人格快照不算新证据、选材按相关性不按稳定期、**可变字段只能由事件累加**（⑨）。
>
> **二、每个"该不该"都必须能返回"不"。**
> ⑤ 是 ① 的前提：如果 gate 不能返回 allow=False，"时机与内容分离"就只是把一次调用拆成两次。
>
> **三、回路不是敌人，无标记的回路才是。**
> xinchao 有意建了驱力↔记忆的回路并封顶；surf 有意建了好奇心回路并加闸。我们建的动量、悬置、强化全是回路。**区别只在于：有没有一个地方写着"到此为止"。**

## 4. 怎么防止这些被改回去

每一条不变式在测试里都有对应，而且每一条都做过**回退验证**（把修复改回原样，看测试是否变红）：

| 不变式 | 测试 | 回退后 |
|---|---|---|
| ② 只认外部信号 | tests/test_regulation.py::test_自己开口不给自己加底气 | 2 failed |
| ③ 翻篇闸 | tests/test_clean_rumination.py::test_问不出东西的事会被翻篇 | 1 failed |
| ③ 快照不当证据 | tests/test_persona_night.py::test_历史人格快照不算新证据 | 1 failed |
| ③ 选材不自强化 | tests/test_spectrum.py::test_频带名额按相关性分_不是按稳定期 | 1 failed |
| ④ 不制造差异 | tests/test_peer.py::test_一分钟的漂移应该几乎为零 | 1 failed |
| ⑥ 慢的封顶 | REINFORCE_MAX_GAIN；attention 夹在 [0.5,2]×anchor | 已验 |
| ⑦ 不串域 | tests/test_e2e_world.py::test_副本上私有的东西还是私有的 | 已验 |
| ⑦ 私信不串台 | tests/test_e2e_world.py::test_私信投影出来的节点带正确的域 | 已验 |
