# 外面的世界：天气与位置（读数不是记忆）

> Amap（高德）Web API：实况天气、IP 定位、地址解析。
> 目标不是"给她加一个天气插件"，是让她**知道此刻外面是什么样子**。
> 这两件事差得比听起来远。

## 1. 三种东西，不能混

系统里现在有三类外部输入，各自的寿命和语义完全不同：

| | 例子 | 寿命 | 会衰减吗 | 重放要等价吗 |
|---|---|---|---|---|
| **事件** | 他说了一句话、她回了一句 | 永久（唯一真相） | 不衰减 | 是，逐字节 |
| **记录** | 生日、纪念日 | 永久 | 不衰减 | 是 |
| **读数** | 天气、位置 | 几小时 | 过期就不作为"此刻" | 是，但读的是**当时**的值 |

读数是新的一类，它的定义是：**世界此刻的样子，会被别的东西改变，不是谁的经历。**

据此推出三条实现约束，每一条都对应一个具体的坏法。

---

## 2. 读数必须是事件（不是实时查询）

最省事的写法是装配上下文时现取：

    def render_b(...):
        weather = amap.fetch()      # ← 错

它错在**重放**。events 是唯一真相，夜里 `replay --shadow` 会用日志重建整个投影。
如果天气是现取的，重放时她"看到"的是今天的天气，而她当时回答的是三天前那个雨天——
**"她那天说的话"无法复现**，而这套系统里所有的验证都依赖这个。

正确写法和我们处理 `msg_in` 完全一样：

    取到 → append_event(source="amap", kind="reading",
                        ext_id="amap:weather:330100:2026-11-26 14:00:00",
                        payload={weather, temp, humidity, wind, report})
    装配 → 读最近的 reading 事件（按 report 判断新鲜度）

幂等键里带 **观测时间**（`reporttime`），不是我们取的时间：
同一份观测重复采集 = 同一条事件，不会因为 tick 跑了两遍就落两条。

`reading` **不投影成节点**。她记得住的是经历，不是气温。
`project.restore()` 的 kind 白名单里没有它，它自然被跳过——这是有意的，
不是漏了。

## 3. 位置是配置，不是 IP 猜的

这一条是实测出来的，不是想出来的。

```
$ curl "https://restapi.amap.com/v3/ip?key=..."      # 开发机
{"province":"浙江省","city":"杭州市","adcode":"330100"}

$ ssh root@ecs curl "https://restapi.amap.com/v3/ip?key=..."   # ECS
{"province":"浙江省","city":"杭州市","adcode":"330100"}
```

两台物理位置不同的机器，IP 定位返回同一个城市。原因很朴素：**她跑在 ECS 上，
IP 定位解析的是机房的出口 IP**。如果他在南京，她会以为外面在下雨（杭州），
然后说一句关于雨的话——**这句话在物理上就是假的**。

所以：

    GITS_AMAP_ADCODE=320100     # 必填。她「在哪」必须显式给
    GITS_AMAP_KEY=...           # 必填

没配就抛，**不静默降级成"没有天气"**——静默降级会让她在某天突然失去天气而没人知道为什么。
（`ghost.world()` 里捕获了它：幽灵不因为没配而崩，但 `gits world` 会明确告诉你原因。）

IP 定位保留，但**只用来核对配置**：

    $ gits world --verify-location
      IP 定位：浙江省杭州市（330100）  与配置不符——IP 是机房位置，以配置为准

它永远不覆盖配置。这是一条硬纪律：**可观测的东西不自动变成权威**。

## 4. 读数不触发开口

最容易滑进去的一步是：下雨 → 提醒带伞 → 一条主动消息。

但我们已经有一条原则叫**墙钟只做参照层，不直接参与行为决策**。天气是同一类东西：
它是**她此刻知道的事**，不是**她此刻该说话的理由**。

区别很具体：

```
"外面在下雨"        事实。她和他看到的一样多。      → 进 B 段
"下雨了记得带伞"    规则替她想的。不是她想起什么。  → 不进 gate 的 reason
```

所以 `gate` 的输入里**没有天气**，主动开口的理由仍然只来自 `unresolved`（悬着的事）
和 `recall`（想起了什么）。天气进 `RelationSnapshot.world`，一小时一换，
和她此刻的心情、说话的样子放在一起——**都是"此刻",都不是"理由"**。

测试直接钉住了这一点：

    for word in ("带伞", "记得", "注意", "小心"):
        assert word not in line

## 5. 新鲜度由观测时间算，不由我们的钟算

`reporttime` 是高德说"这条是几点观测的"。用它判断新鲜度，比用我们的时钟准：

| 阈值 | 值 | 为什么 |
|---|---|---|
| `FETCH_MS` | 55 分钟 | 采集间隔。同一小时内不必再取 |
| `FRESH_MS` | 3 小时 | 超过就不算"此刻"，不进 B 段 |

读数**过期不删**。一小时后它不是"此刻"，但它仍是"当时的世界"——
重放三天前的日志要能读到三天前那个温度。**过期的是可见性，不是事实。**

这也顺带解决了一个隐蔽问题：如果过期就删，晚上的 replay 会把白天的读数抹掉，
于是"她那天为什么提到冷"就再也查不到了。

## 6. 落点

| 文件 | 做什么 |
|---|---|
| `gits/world/amap.py` | 采集 + 落事件 + 出一行 |
| `gits/speech/context.py` | `RelationSnapshot.world`，`render_b` 多一行 |
| `gits/speech/respond.py` | `relation()` 里填 `world=amap.line(...)` |
| `gits/ghost.py` | `world_ms = 30min` 一拍取一次，取不到跳过 |
| `gits/cli.py` | `gits world [--fetch] [--verify-location]` |

幽灵那一拍是**采集**不是**决策**：没有天气是正常状态，不抛、不重试、不加时延。

## 7. 还没做

- **预报**。`extensions=all` 能给 4 天。现在是故意不取：预报是"明天"，
  她活在"此刻"。等出现"她会为了明天做准备"的需求再取——那时候它更可能是**记录**
  （"周六要下雨"）而不是**读数**。
- **逆地理编码**。`regeo` 能把经纬度变成"XX 路 XX 号"。现在不需要：
  我们连经纬度都没有，而且**知道得太具体不是好事**。
- **他所在的城市**。这是**记录**（他说的"我在南京"），不是读数。
  放进 `facts` 比放进这里合适，但 `facts` 现在是日历结构，装不下"地点"。
  等他真的说了再设计。
