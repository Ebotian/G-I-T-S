# 检索：从 0 到 0.78，全程不用向量模型

## 0. 结果

180 天 × 3 个种子，同一批间接提问：

```
              r@1        r@5        r@10     找对实体
裸问          0.00       0.00       0.00     —
+ 上下文      0.43–0.61  0.84–0.95  0.96–0.99  1.00
+ 上下文 + r  0.75–0.79  1.00       1.00       1.00
```

**整条链路没有任何 embedding 模型。** 端到端（走 nodes / node_content /
FTS / recall 的生产路径）复现：top-5 命中 1.0，@1 ≥ 0.5（10 条抽样）。

## 1. 三层能力，各管一件事

| 层 | 管什么 | 机制 |
|---|---|---|
| 词面 | 不会漏字面重叠的 | FTS5 + 字符二元组 |
| **上下文** | **是指谁** | 把最近几轮原文拼进查询 |
| **r（FSRS）** | **是哪一条** | 可提取性；被取代的旧版本 r=0 |

「上次那个跟你较劲的事」之所以说得通，是因为**上一句还在聊它**——
指代是靠对话解析的，不是靠记忆库。

而同一实体的多条事实字面**完全一样**（`物07 状态 卡住了` 被说过三次），
这时相似度没有任何信息，能区分它们的只有「还活着吗」和「还记得住吗」。

## 2. 我自己埋的一个坑：上下文里用了实体 id

第一版上下文生成写的是 `e003 偏好 想换掉`，而节点正文是 `物03 偏好 想换掉`——
**两者一个词都不重叠**。于是上下文形同虚设，@1 只有 0.60。

改成名字之后：@1 0.60 → 0.78，@5 0.90 → 1.00。

教训和之前那次一样：**生成器的一个小缺陷会让整个结论偏保守**。
前一次是「纯泊松提及 → 间隔效应测不出来」，这一次是「上下文缺主语 → 上下文扩展被低估」。

## 3. 方法论限制：@1 的标准答案是什么

这份数据的「正确答案」定义成**最近被提起的那条**——这本身偏向任何感知
新近度的打分器。分层实测：

```
答案同时也是「提得最多」的   @1 = 0.85   (35/41)
答案只靠「最近」           @1 = 0.48   (29/61)
```

第二行说明 FSRS 不只是复读最近：一条提过很多次但久未提起的事实，它的 `r`
可能高于一条刚提过一次的。真实场景里两种都可能是他对的意思，
所以这个数应该读成「与一个『最近优先』启发式的吻合度」。

**能确认的是：找对实体 1.00，答案进 top-5 1.00。**

## 4. 分词：二元组，不用 jieba

| 方案 | 代价 |
|---|---|
| jieba | 默认词典常驻 **~50 MB RSS**，而 ghost 的预算只有 120 MB |
| **字符二元组** | 索引大一点；无词典、无 OOV、内存零 |

## 5. 三个 bug（都不报错，只是结果错）

**① `bm25_to_sim` 方向写反。** `1/(1+|rank|)`——bm25 越负越好，这个映射让
匹配越好的分越低。对照命中率从 0 变成 0.82 才暴露。

**② 命中文档的相似度不能是 0。** 每个词在所有文档里都有时 IDF≈0、bm25=0，
但那条**确实命中了**。映射成 0 就和「没命中」混在一起，排序退化成插入顺序。

**③ 向量如果只做重排钩子，就永远救不回词面漏召的节点。**
`max(fts_sim, vec_of(id))` 是错的，得是并集。

**④（格式）`- - 1 小时前`。** `Recalled.line()` 和 `render_c()` 各加了一个 `- `。

## 6. embedding 提供商：都查过，都不行

| 方案 | 规模 | 能否进 ghost（120 MB） |
|---|---|---|
| `potion-multilingual-128M` | Model2Vec 静态向量，bge-m3 蒸馏，256 维 | fp32 ≈512 MB ✗ |
| `bge-small-zh-v1.5` | 512 维，≈40M 参数，≈80 MB RSS | ✗（ghost 已用 30 MB） |
| `bge-m3` | 1024 维 | 只可能在工作机上 |
| DeepSeek API | — | **没有 embedding 接口**（VERIFIED §3） |

硬件事实，不是选型。主线是 **上下文 + r**；向量留在 `candidates_of` 钩子上，
哪天真有提供商或工作机闲置算力，接上去同一个 `eval_search` 立刻能量出它补回来多少。

## 7. 打分公式

```
score = 0.55·sim + 0.25·r + 0.10·energy + 0.05·centrality + 0.05·recency
```

线性、可解释、可消融。**它不是概率**，只用来排序。
权重是初始值，等有真实查询再调——现在调等于拟合噪声。

## 8. 现在能跑的东西

```bash
gits --db mem.db recall "那个老是出问题的家伙" --context "物03 偏好 想换掉"
gits --db mem.db turn   "那个老是出问题的家伙" --context "物03 偏好 想换掉"
```

`turn` 会把 A/B/C 三段拼出来，回收的记忆就在 C 段的「你想起来的事」里：

```
# 你想起来的事
- 1 小时前：物03 偏好 想换掉
- 1 小时前：物03 抱怨 想换掉
```
