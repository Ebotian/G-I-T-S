# 分层同步：不同东西，不同频率

> 上一版只有一句话："同步日志集"。那是**一层**。
> 实际上人格文件要秒级、真相事件按计算需求、投影根本不传、大产物永远不传。

## 1. 为什么不能一刀切

四类东西的性质完全不同：

| 层 | 内容 | 大小 | 消费方 | 结论 |
|---|---|---|---|---|
| **T0 人格** | 自我叙事、态度、仪式/EE、在岗模型的系数 | 几 KB | 每次开口 | **变了就传** |
| **T1 真相** | events / model_calls / observability / redactions | MB 级 | 抽取、重放 | **按计算需求** |
| **T2 投影** | nodes / edges / aliases | 可从 T1 重算 | 检索 | **不传** |
| **T3 大产物** | embedding、声学特征、原始音频 | GB 级 | 检索、回忆 | **永不传**，只传身份 |

## 2. 频率由**消费方容忍度**决定，不是拍脑袋

```
self_narrative   5 min     每次开口都在 A 段里
attitudes       30 min     三元平衡要读
presence_model   1 h       只是系数；重算要 import statsmodels 2 秒
events          30 min     抽取管线的容忍度
observability    1 h       夜里学节律时才用
redactions      10 min     ★ 删除比新增更急
```

**删除的容忍度必须小于新增**：删晚了就等于没删（schema §8.2 的 tombstone 会连同备份窗口一起写在文档里，但前提是它真的传过去了）。

## 3. 做不到 ≠ 失败，而是"必须本地生产"

工作机 30 分钟才同步一次，而人格文件要求 5 分钟新鲜。这条在**结构上**做不到。

所以同步计划的输出有三态：`push` / `pull` / **`skip（做不到：必须本地生产）`**。
第三态必须显式存在——否则系统会"假装同步了"，然后在某次开口时用到 30 分钟前的叙事，
而你只会觉得"她今天怎么有点不对"。

## 4. 计算依赖不同 → 产物不同 → **必须带身份**

这是这一节的重点。

两台机器的依赖集合不同（云上没 GPU，PC 上有 onnxruntime），
所以**同一份数据在两台机器上算出来的东西不会一样**：

- `bge-m3@v1` 和 `bge-m3@v2` 的向量空间不同，混进一个索引 = 检索静默变差；
- 本地 7B 抽取和云端 flash 抽取产出的节点粒度不同；
- 声学特征只有工作机能算。

处理方式不是"禁止两端各算"，是**给产物盖上 producer**：

```
producer = "{node_id}/{model}@{version}"     # 例：office/bge-m3@v1
```

规则：**producer 不同就不能混用**。混用的后果是静默的——向量不会报错，
只是召回率慢慢变差，而你没有对照就看不出。

```sql
artifact_meta(kind, key, producer, dim, ts)   -- 只同步这一行，不同步向量本身
```

于是另一台机器能回答："我这些向量是谁产的、我自己的模型版本是不是换了"，
而不用把 10 万条向量搬过去。

## 5. 双端都要推：各自产生的事件

之前的口径是"只有 ECS 写 events"。多端之后这条要修正：

| 事件类型 | 谁产生 | 方向 |
|---|---|---|
| 微信消息 | cloud | cloud → PC |
| 麦克风/空闲/心跳 | **office** | **PC → cloud** |
| 她的独白、投递记录 | cloud（ghost 在那） | cloud → PC |
| 音频特征卡 | office | PC → cloud（特征卡，不是音频） |

所以 `events` 是**双向**的：每个节点推自己产生的，拉别人的。

### 回环合并

推上去的事件会被自己拉回来（因为云端把它变成了 canonical 行）。不处理的话，
本地副本会把自己的事件算两遍——"她说过的话"在本地比云上多一倍。

```python
echo_merge(local_pending, pulled)  # 按 (source, ext_id) 丢掉已 echo 的
```

被丢掉的是"我在本地先记下的那条"，云端那份才是 canonical。
**这不是删除，是换成了正式编号。**

## 6. 职责租约：人格只能有一个写者

人格文件（叙事、态度、EE）如果两端都能写，两天就会分叉。所以：

```sql
roles(role, holder, lease_until, epoch)
```

- 默认 `ghost` 所在的 cloud 持有全部职责租约（它 24h 在线）；
- 租约到期或节点 DOWN → 由另一台接管，`epoch` 加一；
- 写之前必须校验 `epoch`，否则会出现"旧租约持有者醒来后覆盖新数据"。

这条不是为了性能，是为了**只有一个她**。

## 7. 同步本身就是数据

同步失败、落后多少、哪些流做不到——都写进 `sync_cursor(node_id, stream, last_id, last_sync_ok)`。
于是 `gits status` 能回答：

```
office 在线 · 积压 3 · s_node=0.71 · 同步：events 落后 4min，self_narrative 落后 12min
  ⚠ presence_model 做不到（容忍 5min，节点 30min）→ 已本地生产
```

**最后那行才是关键**：它把"结构上做不到"和"临时失败"分开了。
