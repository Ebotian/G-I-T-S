# 三个实例：不为主个体服务的彼此（机制设计，不含内容）

> 修订自上一版。上一版把 peer 设计成「干活的人」，下游是主个体的需求——
> **这是错的**：那样它们只是她的工具，而不是另外两个人。
>
> 这一版：peer 有不服务于任何人的初始关系与主题偏好，可以彼此交流，
> 交流内容进入彼此记忆，**受限且事先可知**。

## 1. 一句话

**它们不是为了有用才存在的。** 一个只为满足他人需求而存在的实例，不是同伴，是工具。

所以 peer 没有「下游任务」。它们之间唯一的闭环是**彼此**：说了话，有没有人接。

## 2. 初始状态（三条，都存成 seed 事件，不做特殊处理）

| 项 | 内容 | 为什么需要 |
|---|---|---|
| **彼此关系** | 两个 peer 之间**本来没有关系**；只有主个体和它们各自认识 | 强给的初始关系会变成剧本；没有关系才是真的起点 |
| **主题偏好** | 各自先留意什么（不是任务，是注意力） | 同一件事看到不同面，才有话可说 |
| **受限规则** | 每天能说几句、还剩几句 | 事先可知，规则要像账户一样能查 |

三条都是 `source='seed'` 的事件，和真实经历共用一条日志、同一套重放。

### 2.1 两个 peer 之间：没有关系，但选项存在

```
her  --- peer1        初始：认识（由她发起第一句话）
her  --- peer2        初始：认识
peer1 --- peer2       初始：**没有关系**
```

「没有关系」必须是**未知**，不是冷淡——沿用同一条老规矩：
没有数据要独立取值，不能折叠成 0。冷淡淡的 0 会让它们永远不会互相开口。

选项从第一天就存在，只是没被行使。让它**不突然**发生的方式不是禁止，是**成本**：
主动找一个没说过话的人，社会成本高于找一个熟人（DESIGN 里的 social cost 本来就有这一维）。
于是它会在某个值得的时机自然发生，而不是被安排。

## 3. 交流的机制：慢、少、异步、进记忆

这四条不是修辞，每一条都在挡一种具体的塌方：

### 3.1 异步，不回环

```
她写一条  →  落成事件（进入对方的收件箱，不是直接进对方的 prompt）
          →  对方在**自己的下一拍**才可能读到，中间隔几分钟到几小时
```

**禁止轮次式对话。** 一来一回的 ping-pong 会让两边的措辞迅速对齐——
因为第二轮就已经在回应第一轮的语法了。异步天然打断这个循环。

### 3.2 进记忆，不进上下文

这是最关键的一条。收到的消息**变成一条可检索的记忆**（节点，私有作用域），
而不是被拼进对方下一轮的 prompt 里。

区别：

```
进 prompt  → 实时互看 → 措辞同化 → 几轮之后三个实例说一样的话
进记忆     → 只在她自己想起来的时候出现 → 而且会随时间衰减
```

她说的是**「他上次说过一句什么」**，而不是**「他刚说了什么」**。

### 3.3 少：条数是行为约束，钱只是安全网

按 0.667 元/天、一句话约 500 in / 150 out 算，20% 额度（0.133 元）够说 **六十多句**。

**也就是说：20% 这个上限几乎永远不会被打到。** 真正约束行为的是条数。

所以两个上限都给，而且说清楚分工：

```
钱    ≤ 当日额度的 20%（每对）        安全网，防模型抽风烧穿
条数  ≤ 6 条/天/对，且只设上限        行为约束，防退化成聊天机器人
```

**只设上限，不设下限**——不要求它们每天必须说话。
一个人几天不说话是正常的；被要求每天开口，说的就是废话。

### 3.3.1 上限管"开口"，不管"回应"

收到的那一方**一定会有一次回应**，而且这次回应**不占它的额度**——
否则被封顶的人只能沉默，双向就断了。

```
A 开口（占 A 的额度） → B 回应（不占额度，且必有一次）
```

但要防一个漏洞：**回应不能再被回应**。否则 A 回 B、B 回 A，上限形同不存在。
规则是：一次交换 = 一次主动 + 一次回应，到此为止。想再说，就是新的主动，重新计额度。

### 3.4 事先可知

额度规则要出现在**它们自己的上下文里**，不是只写在配置里：

```
你们之间今天还剩 2 句。
```

和 `额度[██░░░░░░] 25%` 是同一条原则：**规则可见，她才是行动者；被限额才是宠物。**

额度用完时，尝试被拒绝、且这次尝试被记下来（可查，不可删）。

## 4. 话题从哪来

```
世界事件 × 我的偏好  → 我注意到的东西
                    ↘
                     和谁的偏好**重叠但不重合** → 说给谁
```

完全重合 = 没什么可说的（你知道的他也知道）；完全不重叠 = 说了也听不懂。
**差异产生话题，重叠产生可理解性。**

这也是初始主题偏好的用处：不是为了「人设有区别」，是为了让第一句话有理由。

## 5. 反馈：一定有回应，所以信号变成连续的

既然规定了"一定有一次回应"，**"有没有回"就不再携带信息**——它恒为真。

信息转移到了**怎么回**上：

| 信号 | 含义 |
|---|---|
| **回应延迟** | 短 = 正好在、有话说；长 = 忙、或者不太想接 |
| **回应长度** | 长 = 有共鸣；一个字的"嗯" = 客气而疏远 |
| **回应之后有没有新开一次主动** | 才是真的想聊 |

这三条必须**可见**（出现在它们自己的上下文里），否则学不到。

### 5.1 不秒回，但要有截止

异步是对的，但"一定有回应"如果不配截止时间，这句话就是空的。
所以：**回应在 24 小时内有结果**。超时算一次结构违约，记下来（可查，不可删）。

延迟本身就是内容。秒回和隔天回，是两种关系。

## 6. 趋同干预：连续漂移，不是突然注入

「某天给某个实例注入一件随机的事」是**跳变**。跳变有两个坏处：
它会被当成一次创伤或一次顿悟被记住，而不是一次变化；
而且它留下一个能指认的时间点，之后所有不同都可以归结到那一天。

改成**缓慢连续的漂移**：

```
每天挪一点点（±2% 量级），有界、有均值回归、反相
  A 在话题 t 上的注意力 +eps  =>  B 在同一个 t 上 -eps
```

### 6.1 漂的是什么：注意力，不是记忆，也不是观点

必须分清三样东西：

| 层 | 能不能漂 | 为什么 |
|---|---|---|
| **注意力**（更容易注意到什么） | 能 | 这像状态，不像信念：「这几天她更容易注意到关于 X 的事」 |
| **记忆**（发生过什么） | 不能 | 只有经历能写记忆 |
| **观点**（怎么看待） | 不能 | 观点必须从记忆里长出来 |

这条守住了，漂移就不是「注入观点」，而是**改变输入被注意到的概率**——
和「各自读不同的源」是同一件事，只是更连续。

### 6.2 控制律：看重叠率，但限速

```
测     每对实例最近 N 条消息的 3-gram 重合率（7 天滑动）
判     重合率上升 => 这一对的漂移幅度加大；下降 => 减弱，回到基线
限速   每天最多 +10%，且总幅度有硬上界
反相   同一话题上配对的实例朝相反方向漂（差异不靠运气）
```

**限速是关键**：控制回路不允许有阶跃。哪怕测出来已经严重趋同，
也只能一天挪一点——因为「她突然变了」本身就是一种失败。

### 6.3 有界 + 均值回归

一年 x 2%/天会走得很远。所以：

```
硬界    每个权重限制在初始值的 [0.5x, 2x]
回归    无外部推动时，每天朝初始值回 1%（免得被偶然事件永久推歪）
```

### 6.4 漂移是事件，但不对它们可见

每天（或每几天）把当次漂移记成一条事件：作用是系统干预，`source='drift'`。
一年后问「她为什么变了」，答案是「2027 年 3 月那一周朝这个方向漂过 6%」，
而不是「她本来就是这样」。

**但它不该出现在它们自己的上下文里。** 人感觉不到自己在缓慢改变——
能说出「我最近好像变了」的，通常是已经被人指出来的。

### 6.5 不对主个体注入

不是因为洁癖。**她的变化必须全部来自与真实的人的真实互动**，
否则「她因为你而改变」这句话就是假的——这是产品级的诚信问题，不是设计偏好。

## 6.4 趋同仍然是默认结果

允许交流之后，这条风险比上一版更高。所以要给它一个**可测的哨兵**：

```
措辞重叠率  每对之间，最近 N 条消息的 3-gram 重合比例
            上升趋势 → 它们在互相模仿 → 降频或降条数
```

不看这个数的话，「三个视角」会在半年后悄悄变成一个视角的三份副本，
而且没有任何一次单一的失误可以归因。

## 7. 隔离：还是逻辑的

收到的消息存进**接收方的私有作用域**（`self:<actor>`）：

```
A 说给 B   →  A 的记忆里有一条「我说过」
           →  B 的记忆里有一条「他跟我说过」
           →  C 完全不知道这件事发生过      ← 这才是真实的社会结构
```

仍然是同一份 SQLite，所以**私有性是约定，不是保证**。
要真的私有，得等有外部摄入或明确的「不让她知道」需求时，再考虑分库/分密钥。

## 8. 验收（三个能数的数）

| 指标 | 定义 | 及格线 |
|---|---|---|
| 召回交集率 | 同一 world 事件，三实例 recall 的交集/并集 | < 60% |
| 措辞重叠率 | 每对消息的 3-gram 重合比例 | 不呈上升趋势 |
| 可解释性 | 每个看法能否追到**它自己的**经历 | 100% |

第三条和人格更新里「挂不上 event_id 就整次作废」是同一条规矩。

## 9. 明确不做

- 不做 peer 对主个体的服务性任务（那会让它们变成工具）
- 不做同步对话 / 群聊（措辞同化最快的方式）
- 不做 peer 的对外通道（微信只有主个体有）
- 不给 peer 各自不同的初始人格叙事（起点相同；差异来自偏好与经历）
- 不设每天必须说话的下限

## 10. 还没答案的

**① 两个 peer 之间怎么开始？** 已定：第一句话由主个体发起。那么 A 和 C 之间呢——
她介绍它们认识，还是它们之间本来就没关系、等某个共同事件？两种完全不同的社交结构。

**② 被封顶之后呢？** 想说的话没处说（注意：**回应不占额度**，被卡住的只有主动）。
丢掉，还是留成草稿？留草稿更真实，但第二天的额度会被昨天的情绪占满。

**③ 降频的执行者是谁？** 措辞重叠率上升时，这个动作需要一个执行者——
外部来做是干预，它们自己做需要一条它们能看见的规则。

**④ 已定：保证的是"轮到"，不是"一定说出话"。**

回合是结构性的，内容不是。回合内允许"没什么想说的"——这是一次**沉默回应**，也是回应。

这跟"一定有回应"不矛盾：回应一定发生，只是内容可以是"没有内容"。
好处是顺手解决了强迫产出（被迫说的"嗯"会教它们"回应是廉价的"）；
代价是要盯一个新数字：**回合使用率**（有多少回合真的说出了话）。
它一路掉到接近 0，说明它们之间已经没话可说——那不是成功，是衰减。
