# 记忆漏斗：不是分层，是容量 + 复现

> 一句话：**容量决定漏斗的形状，复现决定上升的动力。**
>
> 没有"人格表"，没有"语义记忆层"，没有禁词表。
> 所有门槛都是可数的：条数、间隔、跨度、深度、压缩比。

## 1. 为什么不是分层

分层记忆（工作/情景/语义）的问题是**分层是输入**：要存一条记忆，先判断它属于哪一层。
判断错了，后面全错。

漏斗是**分层是输出**：所有东西生下来一样，是容量和复现把它们压扁的。
一条变成"慢的"，是因为它被压缩过，不是因为它被判定为"语义记忆"。

区别不是措辞。前者会腐化——总有一天有人加一个 `is_semantic` 字段；
后者没有地方可加。

## 2. 两条机制，别混

| | 遗忘 | 压缩 |
|---|---|---|
| 触发 | 没人再提 | 被**独立地**反复重新推导 |
| 结果 | r 掉下去，检索不到 | 原件被吸收，进不了检索 |
| 可逆 | 可逆（想起来还能回来） | **不可逆，而且有损是设计目的** |
| 例外 | — | 一次性记忆**绝不压缩** |

最后一行是本设计最重要的一条：

> 压缩会把「想不起来」变成「模模糊糊记得」，而后者是编造的开始。

汉堡店的位置忘了就是忘了。压成「他以前住的地方附近有家汉堡店」比忘掉更糟——
因为忘掉时她说"不知道"，而模糊记得时她会编。

## 3. 什么叫「独立重述」

```
gap >= max(上一次的稳定期 s, 半天)   →   算一次独立重述
```

两个设计点：

**用 s 当尺子，不用墙钟。** s 是"这条记忆本来能撑多久"。间隔超过它，才是真的重新提起；
没超过，只是同一段叙述的延续。这也让墙钟继续不参与决策。

**为什么还要半天的最低间隔。** 同一个下午连发三十条，s 很小、间隔也小，
但它显然不是三十次独立重述。

> 实测：FSRS 的曲线比直觉平得多（s=1 天时，10 天后 r 还有 0.55）。
> 所以一开始想用 `r < 0.3` 当门槛是错的——那意味着要等两个多月，
> 那不是"不同时段"，是"不同的季度"。

## 4. 触发条件

```
压缩   条数 > 24  且  独立重述 >= 2      才允许，缺一不可
加深   独立重述 >= 3  且  跨 >= 3 个不同的周   才允许再往上压
容量   每层的目标条数只是**上限**，不是配额（绝不为了腾地方而压缩）
```

为什么要有条数：容量是形状。为什么要有复现：复现才是意义。
一个下午的三百条永远不满足复现条件，于是它永远不压——
它们只是静静衰减，不占检索名额（检索按 r×相关度排序，不按槽位）。代价只有存储，
我们一年 4MB。

## 5. 大词不是禁止，是有门槛

语言里本来就有大量空洞宏大的概念。禁词表是错的路——你禁了"善良"，它写"温和"。

所以门槛是**证据广度**，而且可数：

```
depth 0→1   至少一个实体名 + 一个具体事件或时间点
depth 1→2   至少一个实体名（不能全是关系词）
depth 2→3+  允许抽象，但要求支撑它的独立重述覆盖足够多的周
```

| 现在能不能说 | 条件 |
|---|---|
| 「他又因为那个 PR 跟人吵了一架」 | 随时 |
| 「他在意别人怎么看他的工作」 | 8 件不同的事、跨 1 个月 |
| 「他很善良」 | 30 件、跨 3 个月 |

**"他很善良"不是被禁止，是现在没资格说。** 到点自然解锁。

## 6. 不可逆 ≠ 不可审计

```
子内容：进不了检索（想不起来了）      ← 这就是不可逆，设计目的
        但保留 id 和内容（查得到）      ← 这是账本，不是后路
```

没有人能靠它想起来，但一年后问"她这句话从哪来的"，能顺着 `absorbed_into`
一路走回原件。

这不是回退机制。回退是"把旧版本装回去"，我们不做；
这是一条只读的账。

## 7. 摘要怎么才不会压成格言

三条：

1. **保留最不相似的样本**（3 条），不是最典型的。典型的会强化摘要已有的东西，
   不相似的才留得住纹理。
2. **摘要必须含具体指称**（人/地/东西/具体的事），否则不落库、保留原件。
3. **压缩比随深度递增**。如果 depth 3 的压缩比和 depth 1 差不多，
   说明摘要没在抽象，只是换了个说法——漏斗变成了复读机。

## 8. 人格是这个机制的产物

```
人格 ≈ 独立重述次数最多 × 时间跨度最长 × 压缩深度最深 的那几条
```

三个维度指向同一件事：**它在不同的时候、不止一次地被重新推导出来**。

可证伪的检查：把节点按这三个维度排序取前 20 条，读起来像不像一个人？
不像，说明漏斗没在工作，不是"人格没调好"。

还有一条健康指标：

```
压缩深度直方图应当单调递减
depth 0: 几千   depth 1: 几百   depth 2: 几十   depth 3: 个位数
```

平坦就不是漏斗，是普通的摘要堆。

## 9. 簇怎么定义

**实体锚定**：所有 `mentions` 到实体 e 的节点。

不用向量的理由很硬：ghost 预算 120MB，任何 embedding 模型都放不进去
（bge-small-zh 就要 80MB，potion-128M 要 512MB）。
`mentions` 边是抽取时已经在写的，零成本。

代价："主题相似但没有共同实体"的记忆归不到一起。
可以接受——**真正会被反复提起的东西一定有名字**。

## 11. 已经实现的部分

`gits/funnel.py`：

```python
cluster_of(db, entity)  →  条数 / 独立重述 / 跨度 / 周数
can_compact()           →  条数 > 24 且 复现 >= 2
can_deepen()            →  复现 >= 3 且 周数 >= 3
compact(db, entity)     →  模型调用 → 落事件 → 落投影 → 吸收子节点
```

测试在 `tests/test_funnel.py`，用合成数据（不花钱）：

- 同一个下午三十条 → 复现 0，**不压**
- 隔 20 天四次 → 复现 3，可加深
- 间隔短于稳定期 → 复现 0（她还没忘，不算重新想起来）
- 没有复现 → 连模型都不调
- 压出来的摘要在检索里，原件不在
- 压倒的东西能被 `project.restore` 重放出来

## 12. 还没做的

- 蒸馏调度：什么时候跑、跑几个实体、预算多少
- 深度 2 以上（现在只验证了 1 → 2）
- 与人格的关系：A 段还没改成「从自我域节点里选」，仍读 persona 事件
- 压缩比 / 深度直方图还没有 CLI 视图

## 6. 锚点从数据里估（唯二还会漂的东西）

> 起因：种子里写的 `"开会": 1.2` 是个**静态先验**。
> 权重本身会漂，但漂移的锚点就是那个 1.2——所以无论过多久，它都会回到 1.2。
> 这就是魔法数字的永久后效：种子的作用本该是「头几天多留意一点」，
> 而不是「永远多留意一点」。

现在锚点自己也是估出来的：

```
每天：锚点 ← 锚点 + 0.05 × (目标 − 锚点)
目标 = 1 + 2 × (这个话题最近 7 天的提及次数 / 该实例的平均提及次数 − 1)
没人提 → 目标 1.0（中性）→ 指数衰减回中性
```

于是：

| 情况 | 结果 |
|---|---|
| 种子写了 2.0，三个月没人提 | 回到 1.0，偏好自己消失 |
| 一直提，且明显多于别的话题 | 锚点涨上去——但那已经**不是种子在起作用，是生活** |
| 从没被种过、但一直被提 | **自己长出来**（≥3 次），注意力不该冻在种子那一刻 |
| 偶尔提一次 | 不长出新话题 |

### 6.1 锚点是相对的

`目标` 用的是「相对平均」而不是绝对次数。只有一个话题时，它永远是 1.0——
因为「多」和「少」只有在比较里才成立。这不是缺陷，是刻意的：
注意力本来就是排序，不是绝对刻度。

### 6.2 撞上的一个坑：指数衰减的尾巴会卡在阈值上

第一版写成「每天挪动的幅度小于 0.01 就不动」——听起来像省事，实际是**永远回不到中性**：

```
base=1.19 时，每天挪 0.05×(1.0−1.19)=0.0097 < 0.01 → 停下
```

指数衰减的尾巴正好落在阈值上，于是它停在那儿，看着像「已经回到中性了」，其实差了 19%。

改成：**一直挪，阈值只决定值不值得记一条事件。**

这个 bug 的特点是「数值看起来合理」——1.19 不是 0，也不是 2，不显眼。
要没有「三个月后必须约等于 1.0」这条断言，它会安静地存在下去。

## 7. 统计沉淀：edges 是个矩阵，我们之前只写了不读

> 起因：讨论「沉淀的记忆该不该是概率/张量」。
>
> 结论：**结构已经存在**——`edges(src, dst, w, …)` 就是一个稀疏矩阵，
> `src` 是事件、`dst` 是实体。真正的毛病是**没人读 `w`，而且它从不衰减**：
>
> ```
> attention._mentions  →  count(*) 数行数，根本不看 w
> funnel.cluster_of    →  只要 src 的 id
> grep 'FROM edges'    →  只有 dump 和 wipe
> ```

上了张量也救不了这件事：一个存了但没被读的矩阵，加维度之后仍然是没被读。

### 7.1 改成了什么

```
每次共现   w ← w · e^(−Δt/τ) + 1        τ = 30 天
读的时候   P(dst|src) = w / Σ w          行归一化
```

`gits/graph.py`：`add_edge()` / `effective()` / `mentions_of()` / `sources_of()`。
零新表、零新依赖。

### 7.2 两条必须守住的纪律

**① 存的是「上次共现那一刻的值」，衰减在读的时候算。**

把 `now` 写进存储，`project.restore` 就不再确定：同一个日志、不同时间重放，
会得到不同的图。而 `edges` 在 `PROJECTION_TABLES` 里，它**必须**能从事件重建。

`add_edge()` 只用事件的 ts，不看 now——所以重放两次结果完全一样（有测试）。

**② 成员资格不跟权重归零。**

```
行存在         = 共现过，永久
w 衰减到 1e-40 = 强度没了，但仍然「共现过」
```

这两件事共用一行两列（`w` 和 `last_coact`），但语义不同。
混在一起的话，十年后的簇会因为权重太弱而**静默消失**，
漏斗再也不压它，而且不报错。

### 7.3 一个被我写错的查询方向

第一版只有一个 `probabilities(db, node)`，`WHERE src=?`。
但「这条记忆提到的东西」和「关于它的记忆」是**两个方向**，用同一个函数必错其一。

现在是 `mentions_of(episode)` 和 `sources_of(entity)`——名字不同，方向不同，
没有默认值可以蒙混。

这类错误的特征是「跑得通、数值也像样」，只有测试能抓：
`sources_of` 的键是 `dst`，写反了就成了 `src`，
于是你要的那几条记忆变成了「这几条记忆各自提到过它」。

### 7.4 还没做的：不确定性

现在所有参数仍然是**点估计**：`s = 3.0`，没有区间。
概括应该带着「支撑 N 件事、跨 D 天」，而不是只带一个门槛（`MIN_RECUR`）。
这不需要张量，只需要在概括节点上多存两个整数——等有内容了再说。

### 7.5 什么时候才值得上低秩分解

给一个可测的触发条件，而不是「感觉需要」：

```
实体数 > 500   且   行内 w 的分布明显长尾（少数实体占了大部分质量）
```

到那之前，稀疏计数 + 行归一化能做完全一样的事，而且每一步都看得懂——
**看得懂**这件事在当前阶段比精度重要：她还没开始生活，先别急着给她建潜意识。
